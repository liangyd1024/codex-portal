# Remote Codex Manager

用本机网页管理本机和远程 Codex。两台机器各有独立的管理器数据库，连接通过 SSH 复用目标机的专用 Codex 服务。源码最初直接从 Ally 当前安装目录建立 Git 基线。许可证为 Apache 2.0。

同一会话同一时间只从一个入口操作，由使用者人工约定。本项目没有跨入口控制锁；`turn_owners` 仅用于输出采集归属。

## 配置与运行

需要 macOS、Node.js 22+、Python 3、Git、age。上传和下载 Release 附件还需要已登录的 GitHub CLI (`gh`)。从官方发行渠道安装工具。

将 `config/connections.example.json` 按本机情况填写为：

```text
~/Library/Application Support/RemoteCodexManager/connections.json
```

实际配置置于仓库外，权限为 `600`。`machineId` 必须稳定；连接的 `id` 用于状态文件、`?host=` 路由及浏览器缓存，后续不要随意修改。Ally 保留 `local`（Ally）和 `work-mac`（Marco）；Marco 使用 `local`（Marco）和 `ally`（Ally）。`alias` 只负责展示。

每个连接需设置真实用户名、HOME、Codex 二进制路径；SSH 连接另需地址、端口和本机私钥路径。私钥不复制到另一台机器、不进入备份。双方主机公钥必须事先核验。SSH 强制使用配置的密钥和严格主机校验。

开发运行：

```sh
node server.mjs
```

本机正式网页固定为 `http://127.0.0.1:4317`。手机本地代理使用 `4318`，手机局域网 HTTPS 使用 `4319`。开发预览固定使用 `4327`。未经用户明确要求不得改动这些端口。端口占用时先查原因，不自动换端口。

开发预览使用 `RCM_PORT=4327 RCM_MOBILE=0 RCM_STATE_DIR=/absolute/new/preview-state node server.mjs`，独立保存网页状态且不绑定手机端口，避免恢复既有订阅。仍连接同一目标引擎，请仅操作独立测试会话。

## 账号与用量

侧栏 Codex 标识上方显示所选目标的登录身份。ChatGPT 账号显示邮箱，旁边保留剩余额度；原生接口未提供邮箱时显示“ChatGPT 账号”。API Key 模式显示“API Key”，不显示账号额度。

当前原生接口不提供 Key 前缀或后缀，因此不显示 Key 片段。身份信息每分钟读取一次，断开连接时隐藏。读取失败显示“账号信息暂不可用”，后续自动重试；不保存账号凭据。

## 手机系统通知

iPhone / iPad（iOS 16.4+）需要通过浏览器分享菜单“添加到主屏幕”，再从主屏幕图标打开，在“工作区详情 → 设置 → 任务通知”开启并允许通知。普通浏览器标签页不能开启。主屏幕应用如提示配对，请使用本机生成的配对码登录。Android 使用支持通知的安全浏览器连接。

通知仍来自网页收到的原生任务事件；页面关闭或被系统暂停期间不实时推送，重新打开并恢复连接后补发。系统是否展示横幅受设备通知设置影响，可点“测试通知”检查。

## 定时任务

右侧“工作区详情 → 定时任务”读取所选目标机器的 Codex 原生任务，支持搜索、状态筛选、查看提示词、最近触发时间和原生运行记录。列表打开时每 15 秒刷新，也可手动刷新。RCM 不保存任务副本、不解析自然语言生成任务、不计算下次执行时间、不触发调度；任务与桌面共用同一份原生数据。

首次使用，在目标机器的 Codex 桌面新建并打开一条专用管理会话，然后在网页首次点击“新建任务”时选择并绑定。绑定后固定使用该会话，不提供更换入口。任务列表采用“…”操作菜单；点击任务名称查看详情，编辑和删除先显示该任务详情及管理方式，明确点击“前往管理会话”后才打开这条会话并填写草稿。新建任务也通过该会话准备草稿，已有未发送草稿不会被覆盖或追加其他任务的指令；请先处理原草稿，再返回任务入口继续。尚未接通桌面的直接编辑接口、立即运行和分享，不提供对应的直达操作。发送后由桌面会话调用原生工具完成。任务变更是否成功以原始工具结果和回复为准；“消息已接收”不表示任务已变更。网页不接管这条会话，不修改其模型设置；当前管理入口支持文字输入、停止当前轮次和历史查看，图片、模型切换及需要回答的工具确认在桌面处理。

桌面需保持运行，并拥有这条管理会话。接口不兼容、桌面关闭或会话不再托管时，网页保留草稿并提示恢复，不改用独立引擎执行。发送结果不明时先核对原始会话；自动读到相同消息标识会确认回执，否则需点击“已核对会话记录，解锁发送”。同一会话仍需遵守单入口操作约定，这不是跨入口互斥锁。

当前接入的是已核验版本的原生桌面协调协议，属于内部版本化接口，并非稳定公开 API。任务列表只读支持传统本地任务存储；遇到多份候选数据库、未知结构或账户迁移时拒绝猜测并提示在桌面查看。Heartbeat 的执行结果保留在原会话，未必有独立运行表记录。纯 CLI 目标没有桌面调度能力；SSH 目标还需对应用户运行兼容桌面，目前仅本机完成真实验证。升级 Codex 后若协议不兼容，需更新适配，不能修改原生引擎或存储来绕过限制。

实现与验证范围见 [定时任务验收记录](docs/verification-2026-10-19-native-automations.md)。

## 安装指定版本与回退

“重启”“重新部署”默认仅指 RCM 系统的网页管理服务，不包括 Codex 桌面应用、原生引擎、目标机服务或会话任务。其他组件的停止或重启须另行明确授权并遵循维护检查；不得通过中断任务实现 RCM 重启。网页连接会短暂断开并自动恢复。

开发目录、后台版本目录、运行数据目录各自独立。`git pull` 仅更新开发目录。

代码逻辑修改、功能修复或优化验证通过后，自动在 `master` 提交并推送到 `origin/master`。随后重新部署本机正式网页，无需再次确认。用户要求仅改代码或暂不部署时，不部署。纯文档变更不部署。

部署前对比当前正式版本，保留已上线的其他功能。当前部署会话仅按下述规则豁免，其他空闲检查未通过时不得绕过或停止在用任务。提交并推送后执行：

```sh
node scripts/install-local.mjs --ref <commit>
```

安装从 Codex 执行环境的 `CODEX_THREAD_ID` 识别当前部署会话，仅豁免本机连接中同一会话的 `active` 状态，不需要手工传入或硬编码 ID。没有该变量时按普通空闲检查执行；其他运行会话、任何待处理请求及连接中状态仍会阻止部署。此例外不适用于目标引擎维护或数据恢复。

安装会在备份前及重启前检查当前网页入口，生成加密备份，再将 Git 提交安装到 `~/Library/Application Support/RemoteCodexManager/releases/<commit>`。旧安装、副本和配置不删除。仅重启本机网页服务；不会停止目标机引擎或更新正在运行的输出采集器。新版本健康检查失败会恢复原网页 plist。要回退，使用同一安装命令指定之前的兼容提交；需要回到最初基线时使用 `install-history/` 中保存的旧 plist。

原始基线仍位于 Ally 的 `~/Library/Application Support/RemoteCodexManager/app`。开发代码位于 Git 工作目录；后台服务运行不可变的 release 目录。

已有手机入口继续使用原 `mobile/config.json` 和证书。安装不会自动创建手机入口；在本机正式工作台的“工作区详情 → 手机访问”点击“开启同一 Wi-Fi 访问”，即可创建证书和二维码，并启动 HTTPS 入口，无需重启网页服务。手机需与 Mac 在同一网络，并安装、信任页面提供的证书后扫码配对。未开启入口时不能生成配对码；失败可重试。开发预览（`RCM_MOBILE=0`）不开放此操作。

局域网配置使用 macOS 自带 OpenSSL 和 CoreImage，不依赖 Tailscale 或额外的 Python 二维码包。已有 Tailscale 入口会保留；新建跨网络入口可展开“Tailscale · 跨网络访问”并点击开启；需要两端登录同一 Tailscale 网络。程序核对 HTTPS Serve 转发成功后才公布地址，发现既有服务冲突或公网 Funnel 会拒绝覆盖。

## 网页系统更新

右侧“工作区详情 → 设置 → 系统更新”的“更新并重新部署”，更新当前网页所在机器的 RCM 服务，不随所选 SSH 连接切换。已配对手机也可使用同一入口。

安装程序记录源码目录和 origin 地址。网页更新仅接受固定的 master：检查干净工作目录和空闲状态，拉取 origin/master，确认包含当前正式版本，快进 master，运行 npm test，再使用现有版本安装程序完成加密备份、网页重启、健康检查和失败回退。已有未提交修改、未推送提交、分叉、测试失败或运行任务都会停止更新，不强制覆盖或中断任务。拉取后若 origin/master 与当前运行版本相同，提示已是最新版本，不执行测试、备份或重启。页面显示当前版本、最近拉取的最新版本和更新前版本。

部署前通过已连接的原生接口重新读取会话状态，不主动连接目标；短暂收尾或重连会自动复查。仍在运行的会话、待处理请求或未稳定连接仍阻止部署。

更新由独立的后台进程完成，网页短暂断开后自动继续核对进度。状态保存在 RCM 自身的 web-update.json，详细输出位于 logs/web-update.log；刷新页面不会重复执行更新。完成后可点击“刷新页面使用新版本”，已有草稿先保存。网页更新不接受仓库路径、命令、版本或会话豁免参数；开发预览不提供正式更新能力。

Git 使用本机原有认证、代理和 SSH 主机校验配置；网络失败会保留原网页服务并显示失败。手动安装与网页更新共用部署锁。异常终止留下锁时，先核对无更新/安装进程和服务状态，再手动删除提示中的单个 deployment.lock 文件；系统不会自动抢占锁或结束进程。

## 连接和维护

点击“新会话”进入独立输入页，选择项目后直接编写首条消息；模型、思考档位、技能和图片沿用同一输入框。首次发送才创建会话，返回不会创建空会话，未发送草稿保留在当前标签页。创建成功但消息发送失败时，在该会话重试；创建结果未知时先核对侧栏，确认未创建后才能解锁重试。当前支持配置项目的本地工作目录，不提供额外的 worktree 或云环境选择。

网页新会话使用所选目录对应的原生项目 ID 创建。首条消息提交、自动标题处理结束后，只读确认会话已落盘，再通过目标用户的原生 IPC 请求刷新桌面会话发现缓存；落盘延迟有限重试，桌面未运行不报错，刷新异常仅写入连接诊断，不影响消息提交。该通知不代表桌面已完成渲染或项目归属同步；桌面项目缓存及迁移仍由 Codex 管理，不能保证立即在项目下出现。

新会话在首条消息成功提交后，用本地代码从消息文字提炼一次标题：清理格式和礼貌用语，优先提取任务句，保留关键标识与否定词，最多 36 个字符；纯图片消息使用“图片会话”。标题生成不调用模型、不消耗模型 Token。后续轮次不再自动改名，已有会话保持原标题；可通过会话菜单手动重命名。命名失败不影响已发送的消息，也不会在后续轮次自动重试。

输入区“＋”支持选择或粘贴图片，每条最多 4 张，支持图片单独发送、预览和移除。手机照片会缩放压缩，发送失败保留文字和图片；附件草稿仅保存在当前标签页的 sessionStorage，容量不足会提示刷新可能丢失。无法解码的 HEIC 等格式需转换为 JPEG / PNG / WebP。图片随消息通过当前连接发送到目标引擎。

回复中的本地文件链接可点击预览或下载，视频和音频使用浏览器播放器，支持进度拖动；也兼容以 Markdown 图片写法引用的视频。图片可放大，PDF 使用浏览器阅读器（未显示时可新标签页打开或下载），文本和代码预览前 1 MiB，HTML/SVG 只显示源码，Office、压缩包等提供下载。文件始终从会话所属连接读取，SSH 使用独立二进制流；不接管会话、不上传到外部服务。仅支持可从目标历史消息核验的绝对路径，受保护路径不可读取；缺失文件、目标离线或历史记录尚未落盘时可重试。纯文本路径不会自动识别，文件移动后不会自动寻找新位置。浏览器编码不支持时可下载后打开；未实现本机应用唤起、Office 转换或 HTML 脚本运行。

“工具”内支持“默认 / 计划”切换，输入区不再常驻“执行 / 默认”控件（默认即直接处理请求），模式在下一轮发送时生效。原生计划成功生成后，输入框上方显示“执行此计划？”并清除计划模式标记；确认后以普通模式发送完整计划开始执行，暂不执行仅收起选项，未发送草稿保留。网页版固定使用“完全访问”：新建会话和发送新轮次均使用引擎的免逐次审批及完整文件、网络访问设置，无需选择授权方式，旧权限偏好不再影响此策略。正在运行的轮次保持启动时的权限；其他 API 客户端未指定权限时仍保持默认权限。

选择“输入框左下角 ＋ → 目标”后，直接在消息输入框填写目标并发送，无需弹框或 Token 预算。新会话会先创建，再将文字交给原生目标能力启动；后续消息补充同一目标，再次选择“目标”才更新目标。点击“目标 ×”取消尚未提交的选择；已有目标可在空闲时通过 ＋ 菜单暂停、继续或完成。输入框输入 `/` 或 `$` 搜索技能，点击候选项或用方向键、Enter / Tab 选择，Escape 关闭。选择的技能以蓝色 `$技能名` 插入光标处；也可通过“＋ → 技能 / 插件”插入。引用属于当前草稿，删除引用即取消使用，发送失败保留，发送成功随文字清空，不再长期沿用上一条消息的选择。网页版使用原生文本编辑，引用可逐字编辑，与手机原生的图标式富文本引用有视觉差异。“技能”和“插件”读取所选项目对应的目标机器目录，选择的技能以结构化输入传给引擎，已启用插件通过明确的文字指令调用。插件安装和账号授权仍在 Codex 中管理。内置语音入口已移除，可使用系统输入法听写。

运行中的异步提问会在输入框上方显示问题卡片，支持选项、自由输入和多题回答，不包含语音按钮。发送时将答案关联到原问题和原轮次；成功后收起，失败保留草稿，结果未知时不会自动重发。“×”只收起卡片，异步问题的“跳过”仅在当前标签页忽略，可点“重新回答”；普通同步问题仍需回答才能继续。问题草稿按连接、会话和问题保存在当前标签页，刷新和切换会话后恢复。仅对仍在运行且由网页控制的会话提交回答；已结束的问题不再显示可回答卡片，不跨入口向桌面端占用的会话发送。

目标状态读取失败只在目标入口提示，不会把整段聊天标记为同步失败。新建空会话的持久记录尚未出现时，临时使用引擎成功创建时返回的元数据；其他存储错误仍如实显示。创建请求超时代表结果未知，请先刷新列表核对，不要重复创建。

部署或服务中断期间，页面显示统一的自动重连提示并保留已有内容和草稿。重连后若部分历史会话未能恢复网页接管，仅当前打开的受影响会话显示提醒，不在正常会话或新会话页显示历史失败横幅；汇总及每个会话的原始原因保留在“工作区详情 → 设置 → 连接诊断”。可打开对应会话重试接管，恢复成功后更新提示；不会自动删除历史会话或失败订阅。

当前打开的会话在网页可见且目标连接可用时，每次读取完成后间隔 5 秒自动同步历史；切回浏览器窗口、标签页或恢复网络时立即检查连接并同步。此行为不受“自动刷新项目和模型”开关控制。浏览桌面端会话和已交还会话读取历史存储，并通过目标用户的本地协调通道短暂观察桌面实时状态，不重新接管或订阅目标引擎；同步失败会保留当前内容和草稿并自动重试。左侧列表常驻一个创建来源图标：电脑表示桌面端创建，地球表示网页端创建（含手机浏览器），来源缺失时提示未知；运行时在同一图标上增加高亮和动态圆点，悬停或无障碍名称说明创建来源及当前运行端。正文输入框上方显示运行图标和明确的运行提示。状态断连、过期或协议不支持时撤去运行标记，保留侧栏创建来源图标。

历史快照出现 `unable to open database file` 时，网页通过已验证的原生 `thread/turns/list` 读取完整历史，不修改原生数据库，也不接管或恢复会话。后续分页沿用原生游标；若加载更早的快照页时才发生故障，会要求刷新会话后重新加载，避免混用两种分页位置。其他读取错误仍如实显示。

切回桌面继续同一会话时，点击网页会话顶部直接显示的“交还桌面端”按钮。程序只检查并退订当前会话，保留历史和网页草稿；有运行轮次、目标、后台命令、待处理请求或排队输入时会说明原因并拒绝交还，不会替用户停止任务。其他会话及目标服务继续运行。

退订成功后显示“等待引擎释放”，只有核对该会话已从本引擎卸载才提示回桌面重试。引擎默认需要在没有订阅和活动后等待约 30 分钟才卸载；其他网页入口仍在使用同一会话时会继续等待。关闭网页或普通断开连接不代表已经交还。交还意图会持久保存，当前入口刷新、重连或重启后不会自动接管该会话；结果未知时可重试交还，需要回到网页时明确点击“在网页继续”。本功能不通过停止整个目标服务来缩短等待时间。

可为连接配置可选的 `threadUnloadDelaySecs`（0–86400 秒），例如 5 秒。程序仅在启动该连接的专用引擎时传入此设置，不修改 Codex 全局配置，也不自动重启运行中的引擎。应用到已有引擎前必须按维护流程确认其他入口断开，并检查所有会话、目标、后台命令和队列空闲；忙时不得重启。此设置适用于该引擎所有无订阅且无活动的会话，不是单次交还的超时，缩短后普通断线的恢复宽限也会缩短。界面仅按实际运行进程的启动参数显示已生效的时间。

“断开本机连接”只断当前入口，专用服务和任务继续运行。“停止目标服务”会影响所有入口：先结束目标上的任务、目标模式、后台命令和排队输入，并断开其他入口，再明确确认。服务会写入维护标记，兼容版本的入口不会自动重连；这不是跨入口控制锁，旧版入口不识别此标记。

专用引擎使用 launchd 的 `Interactive` 调度类别，以保证聊天请求的 CPU 和磁盘响应；它仍是后台运行的服务。旧版 `Background` 类别会受到系统资源限制，可能导致创建及模型读取超时。更新网页不会改变已运行引擎的启动类别，需要按上述维护流程确认空闲后停止、恢复并重新连接，才会使用新配置；不得为加速请求直接重启在用引擎。

完成维护后在目标机器运行：

```sh
python3 scripts/restore-apply.py resume
```

该命令归档维护标记，随后在网页手动连接。不要用停止服务或恢复命令打断其他入口的任务。

## 加密备份

```sh
python3 scripts/data-backup.py key-init
python3 scripts/data-backup.py backup
python3 scripts/data-backup.py backup --browser /absolute/path/browser-export.json
```

恢复私钥在仓库外的 `~/Library/Application Support/RemoteCodexManager/keys/backup-identity.txt`，权限 `600`。请另存到离线介质；丢失私钥后无法解密。私钥不上传 GitHub。默认备份目录为同级 `backups/`。

备份范围严格限定为：

- `output-journal.sqlite` 的 SQLite Online Backup API 快照，含所有表，并检查完整性。不会复制运行中的 WAL/SHM。
- `web-titles-*.json` 及 subscriptions、handoffs、notices、connection、native-automations 状态（管理会话绑定和发送回执，不含原生任务配置）（标题状态可能含消息上下文）。
- 实际连接配置、手机访问配置、配对状态、本项目 CA 和服务端证书/私钥。
- 管理器服务日志，以及显式提供的浏览器导出文件。

排除 Codex 原生数据库、完整聊天文件、Codex 登录文件、SSH 私钥、其他项目或技能凭据、Cookie、socket 和临时文件。输出日志和浏览器详情缓存可能包含已显示过的会话内容；这是管理器自身数据，不代表完整聊天历史。

每份包包含来源机器、UTC 时间、代码提交、格式版本、文件大小、SHA-256、数据库表和缺失项清单。age 加密包超过 1 GiB 时生成分卷，索引记录顺序及校验值；原加密包保留。无定时任务，不自动删除历史备份。

```sh
python3 scripts/data-backup.py publish /absolute/path/backup.age.index.json --repo OWNER/remote-codex-manager --tag backup-MACHINE-TIME
python3 scripts/data-backup.py download --repo OWNER/remote-codex-manager --tag backup-MACHINE-TIME --destination /absolute/new/download-directory
```

## 浏览器数据

在网页右侧“设置 → 浏览器数据备份”导出或导入。范围为当前 origin 的本应用 `rcm.*` 设置、当前标签页 sessionStorage（草稿、视图、输出位置、展开状态）及 `rcm.recovery.v2` IndexedDB 详情缓存。导出前会刷新当前草稿状态；不读取 Cookie。

导出文件记录时间及覆盖范围。其他浏览器、其他标签页和不支持的旧缓存库明确标记为未包含；请分别导出。文件含草稿与缓存内容，交给 `backup --browser` 加密保存。导入前核对来源机器和每个连接指向的目标；不匹配时拒绝。导入合并本应用数据，恢复的缓存不会获得会话控制权，也不会代替网络最新状态。

## 恢复

先下载，解密、校验并在一个不存在的新目录中验证：

```sh
python3 scripts/data-backup.py restore /absolute/path/backup.age.index.json --identity /absolute/path/backup-identity.txt --machine MACHINE --destination /absolute/new/restore-directory
```

这一步不改实时数据。错误密钥、错误来源机器、损坏文件、路径越界或不兼容格式在覆盖前拒绝。不支持自动把 Ally 数据覆盖到 Marco。验证目录是权限受限的明文数据，使用后按你的文件管理规则手动清理。

确需原地恢复时，先结束任务并断开两台网页的全部连接，再在目标机器运行：

```sh
python3 scripts/restore-apply.py apply /absolute/restore-directory --entrances-disconnected
```

程序再次校验文件和本机身份，读取专用服务确认空闲，生成恢复前备份，进入维护模式，再停止本项目网页和专用服务。当前文件、WAL/SHM 均移动到 `restore-history/` 保留；不执行批量删除。替换失败时恢复旧文件和服务。恢复后关闭自动连接、撤销手机配对并保留证书；浏览器数据需另行导入。Codex 原生数据不会迁移。
