# 首次会话读取与最新正文优先

## 改动

沿用原生历史、正文原文、现有缓存和分页。原生交互依据为已有[正文性能验收](verification-2026-10-22-performance-optimization.md)与[轮次导航验收](verification-2026-10-22-turn-navigation.md)，不声称完全复现桌面内部渲染策略。

- 首次 preview 仅读取最新一轮。SQLite 只读查询及原生协议回退均保留正确的更早历史游标。后续完整读取仍使用原来的每页五轮。
- preview 与 fast 详情不等待桌面活动探测。原探测最多等待 1.2 秒；正常刷新继续补齐状态，不伪造运行状态，不改变接管或执行语义。
- 前端先渲染最新一轮，每次最多补齐四个较早轮次，中间让出绘制机会。复用已有消息节点；原始数据完整保留。不是截断、摘要或独立业务副本。
- 修正从单轮 preview 合并到完整页时的顺序，保留 SSE 已收到的更新及新增轮次。切换选择或连接版本使旧批次失效。向前阅读时按可见轮次保持位置。目录跳转可立即展开目标轮次；恢复阅读位置等待相应轮次出现。

没有新增完成后的网络缓存或轮询。现有 IndexedDB 恢复缓存仍按原规则保存。之前打开过的会话可以先显示缓存；首次打开则主要依赖目标读取和正文渲染。

## 性能验证

本机真实接口只读抽样，没有发送、接管或停止业务会话。优化前正式版本为 `c9a0608`，优化后使用 4327 独立预览，状态目录在仓库外。

| 样本 | 原 preview | 新 preview | 原轮数 / 新轮数 |
| --- | ---: | ---: | --- |
| 1 | 194ms | 99ms | 5 / 1 |
| 2 | 1313ms | 101ms | 2 / 1 |
| 3 | 1342ms | 91ms | 2 / 1 |

数值包含 HTTP 响应体读取，是三个动态会话的单次观测。不是固定数据压力测试，也不是用户端点击至显示的时间。新首批仍可能包含较长正文；样本响应约 12KB、269KB、181KB，未截断助手消息。没有给出总体加速比例或百分位承诺。

浏览器使用 ego-browser 和模拟 API，50 轮、每轮 20 段 Markdown，比较首次正文与完整补齐：

| 场景 | 首次正文节点出现 | 下一绘制回调内轮数 | 全部补齐 |
| --- | ---: | ---: | ---: |
| 旧版桌面 | 90.7ms | 50 | 90.7ms |
| 新版桌面 | 16.0ms | 1 | 613.5ms |
| 新版 390px | 23.6ms | 1 | 3681.8ms |

计时从模拟详情请求开始，网络响应为本地 fixture，不能与真实接口耗时相加。新版优先缩短最新正文等待，全部旧内容出现更晚。桌面该样本未记录长任务；390px 仍有 191 / 183 / 63 / 152ms 长任务，不声称所有渲染流畅。实际首批完整页为五轮，50 轮用于已加载大量历史的压力场景。未测 CPU、内存峰值或真实 SSH 冷启动。
