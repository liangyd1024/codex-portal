## 实现与自动检查

将主控制器的 selectThread、applyDetail 移入严格 TypeScript 服务。保留 URL 参数处理、新建页和定时任务视图关闭、桌面模式判断、详情栏收起、旧草稿保存、新草稿恢复、渲染及读取的原顺序。保留 selectionVersion 对迟到成功和失败的保护，不建立另一份会话状态。

可变的定时任务与滚动控制器通过 getter 读取；稍后创建的布局、缓存与刷新控制器通过回调调用，避免初始化阶段提前读取。两函数去除类型并归一 getter 后，运行语法树与原实现一致。详情的未知字段、原文数组及同会话目标对象仍保留引用。

新增四项行为测试覆盖切换前后状态与调用顺序、旧成功／失败不能滚动或覆盖新错误、创建期间阻止切换及可变桌面上下文、详情目标回退与恢复预览不保存缓存。类型检查、构建、完整 852 Node／74 Python 测试通过。干净构建与浏览器候选资源摘要一致。

## 浏览器行为对照

使用 ego-lite 同一页面、正常 React 调试环境。桌面 1480×747／DPR 2／无触控；iPhone 12 390×844、844×390、390×480／DPR 3／触控 1。导航后重新设置设备参数，各样本均记录并核对实际视口、DPR 和触控点数。全部请求进入隔离模拟接口。

草稿往返覆盖 A、B、返回 A、返回 B，四视口 32 样本／16 对一致。比较完整正文、标题、中文草稿、输入禁用状态与历史加载状态，无异常或横向溢出。手机按钮使用触控；短高度目标先聚焦滚入视口，不算实体手指滚动验证。

详情迟到覆盖成功和 409 失败两类响应。选中 B 后暂停详情，切回 A 并恢复草稿，再释放旧响应。初始、旧请求等待、释放前、释放后共 64 样本／32 对一致；另逐流程断言释放前后当前页面完全相同。旧请求成功或失败均未覆盖当前正文、标题、草稿或可用状态。

## 会话切换性能

同一短正文模拟数据，按旧／新／新／旧排列；桌面和手机各四组，每组 45 次切换去除前五次，共 320 个有效样本。通过 DOM click 驱动同步分发，等待输入恢复并读取布局，不等同真实触控到屏幕显示或真实网络时延。

| 设备 | 上一候选同步／帧后中位数 | 本候选同步／帧后中位数 |
| --- | --- | --- |
| 桌面 | 4.30／10.30、4.60／11.20 ms | 4.05／9.70、3.60／9.90 ms |
| 手机 | 6.10／13.20、5.25／11.40 ms | 5.55／12.30、4.80／12.55 ms |

每次均为一次 preview 详情与一次完整详情请求，参数一致；无发送请求、异常或溢出。本组未呈现本次改动的一致性退化，仍有运行波动，不宣称整体性能通过或最优。长会话、输入并发和服务资源门槛仍需另行收口。
