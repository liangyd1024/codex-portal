# 输入提示重复写入优化与复验

## 实现与基准

实现提交 `116f357`，干净资源 `64c268fd3bf1cf79b28fda8b5cacb43465ad50c70114256995a802af369e547c`。正式基准仍为 `227dbfe`。只修改重构分支，没有修改正式服务或原生引擎。

CPU 采样和源码核对发现，输入期间会反复写入未变的提示文字；桌面模式还先写普通提示，再覆盖为桌面提示。当前改动让 setText 在文字相同且没有子元素时跳过写入，并直接选择最终桌面提示。空值仍显示原有破折号，实际文字变化仍立即更新，含子元素时仍按原规则替换为纯文字。没有修改输入、草稿、请求、CSS 或模型选择规则。

交还控件的同类跳过实验未显示足够稳定的增量收益，已撤回并核对该文件与已提交版本完全一致；对应隔离静态进程已停止。实验构建和原始采样保留，不作为交付候选。

## 性能与写入证据

正式资源、上一迁移版 `f0f8ad93`、候选按 A／B／C／C／B／A 交替。桌面与手机各六组，每组 100 次输入，排除 20 次预热，共 960 个有效样本。测量桌面模式约 120 字符草稿的 input 事件到布局读取。

| 设备 | 正式组中位数 | 上一迁移版组中位数 | 候选组中位数 |
| --- | --- | --- | --- |
| 桌面 | 2.70／2.70 ms | 3.40／3.30 ms | 3.00／3.10 ms |
| iPhone 竖屏 | 3.30／3.40 ms | 3.45／3.40 ms | 3.40／3.35 ms |

桌面该场景有局部改善，仍比正式基准高约 0.3–0.4 ms；手机差异较小。不将其外推为全系统提速或性能门槛全部通过。

另在相同桌面和手机场景，各对上一迁移版与候选执行 40 次输入，并用 MutationObserver 记录三个固定提示区域。上一版每组的模型标签、输入提示、模型说明分别写入 40、80、40 次；候选均为 0，最终文字完全相同。四组共 160 次事件，没有发送或解锁请求、异常或横向溢出。该结果确认跳过重复写入生效，不代表全部渲染或布局已最优。

## 占位文案写入实验（已撤回）

正式基准重新核对仍为 `227dbfe`，独立预览保持 `2733e3d`／`1e746526`。该预览实际加载脚本与前轮 `fb290ad3` 相同，隔离对照使用相同脚本资源；本轮没有重启预览或正式服务。

输入属性观测发现桌面接续路径先写普通占位文案，再覆盖为桌面占位文案。实验候选 `ca752e3c` 直接选择最终占位文案，值相同时跳过赋值，禁用状态等逻辑保持。桌面与 iPhone 竖屏分别对照，每组 40 次输入：输入框属性 MutationRecord 从 280 降至 200，最终文字一致，无页面异常或横向溢出。这确认减少了写入，但不等于减少同等数量的布局或绘制。

正常 React 调试／扩展条件下，正式、当前、候选按 A/B/C/C/B/A 顺序，桌面与手机各六组，每组 100 次剔除前 20 次，共 960 个有效样本。计时仍为合成 input 事件到同步布局读取，不代表实体按键到屏幕延迟。

| 设备 | 正式组中位数 | 当前组中位数 | 实验组中位数 |
| --- | --- | --- | --- |
| 桌面 1480×747／DPR 2 | 2.60／2.60 ms | 3.20／3.00 ms | 3.10／3.00 ms |
| iPhone 12 390×844／DPR 3／触控 1 | 3.35／3.20 ms | 3.30／3.40 ms | 3.40／3.50 ms |

两种视口均没有发送或解锁请求，无异常、无横向溢出。候选没有显示稳定收益，手机反而略高。因此撤回占位文案实验，并核对 public/app.js 与已提交版本完全一致；实验隔离服务已停止，构建选择恢复为当前已验证干净资源。未将候选部署至独立预览，未运行完整功能验收，也不计为交付修复。

本轮仅提交测量记录。输入性能差距继续未关闭；原始实验代码、产物及采样保留在仓库外和忽略的构建目录，不与交付验收证据混用。
