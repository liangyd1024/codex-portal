# 工作台启动协调迁移

对照正式源码及 4317 的 `227dbfe`。工作台 init 流程迁入 `src/web/services/workspace-startup.ts`，负责定时刷新、消息展开状态保存、详情分类与延迟安装、ready 事件后的通知路由、首次 CSRF／状态读取及连接恢复。配置读取、事件装配和原生适配继续通过入口传入；模块加载前的 bootstrap 恢复入口未改动。

保留原来的 15 秒账号检查、5 秒控件／侧栏刷新、15 秒侧栏读取，以及可见性、读取中、菜单、弹窗和拖拽条件。设置模块只安装一次，但每次进入设置仍执行原 open；手机模块只安装一次。通知对象保持原引用和未知字段；待处理通知优先于链接。readiness 事件、导航可用标记、缓存恢复、CSRF、状态及工作区刷新顺序不变。首次读取失败继续记录原错误、显示原横幅，并在 finally 结束启动标记。

参数组装留在应用入口，所选账号刷新函数也同步提供给现有事件处理器。该引用原来只在 init 赋值一次，迁移没有增加定时器、请求或独立状态副本。

## 回归

六项新增测试覆盖：启动调用顺序与定时器；延迟安装与动态账号上下文；各类刷新门控；通知优先级和跨目标链接；自动连接／连接中等待／首次读取失败；展开状态的切换前意图和存储失败。类型检查、完整 873 项 Node／74 项 Python 测试与构建通过。

新增浏览器启动夹具只复用隔离 API，显式阻塞首次读取并释放，模拟断开、连接中、CSRF／状态失败及通知。所有请求和写操作由夹具处理，不连接原生引擎。夹具语法检查和浏览器场景均通过。

## 浏览器对照

使用 ego-lite，保持正常 React 调试与扩展。桌面 1480×747／DPR 2／无触控，iPhone 12 参数 390×844、844×390、390×480／DPR 3／触控。导航前后设置设备参数，记录实际视口；手机按钮使用触控。

六类场景在四种视口共 144 个样本、72 对状态一致：

- 正常启动：读取等待、完成、设置、手机入口、重复进入手机入口。
- 未连接：读取等待、自动连接完成。每个流程各一次模拟 connect POST。
- 连接中：等待、保持连接中、模拟连接完成后刷新。
- 首次 CSRF 或状态失败：等待、原错误横幅、用户刷新恢复。
- 同时收到通知和链接：通知优先打开另一会话，恢复对应草稿。

比较连接标签、横幅、标题、草稿、输入和按钮禁用状态、详情分组展开／隐藏属性、关键读取次数及维护写入的完整请求体。手机入口重复进入后 access/status 读取次数始终为一次。无页面异常或横向溢出。

本轮没有重新做所有页面的像素比较或实体通知验证。结果证明上述启动流程的限定保真；不代表全部迁移、原生业务或整体性能门槛完成。首屏资源差异继续保留。
