# 原始正式基准源码的接口差分核验

## 范围与基准

正式 4317 版本接口为 `227dbfe93ee88718c2437f7b7c7b119570a720a6`；预览 4327 为 `accb11f2cfe0e6c1e6563de1560c86540978c4ba`，均返回 200。指定候选构建的 public 与 server 内容重新计算后匹配摘要 `0e4887c7d29f468a80e30e3f66cadc134469600cdab6c2ee7e1f476f801c1ec7`。

已有 framework-http 与 framework-thread-view 测试默认导入重构分支保留的 server.mjs。该文件增加过测试注入及启动适配，因此它不能单独证明对照对象就是原始正式源码。本轮新增 scripts/verify-framework-baseline.mjs，导出指定提交并运行相同接口测试，补齐这一证据。

## 执行方式

入口见 [README：验证](../README.md#验证)。命令要求显式提供基准提交与构建绝对路径，先核验构建资源摘要，再创建全新临时目录。

基准通过 git archive 导出。只将导出目录的 VERSION 设为 fixture，用于两边版本接口的测试常量；不修改基准应用源码。导出 server.mjs 的 SHA-256 为 `cd239213b067f1c31ff51a7ea2997c8ec0fac59f30267233250126d80ac6ce8f`。

临时测试副本仅改导入位置及指定构建路径。调用原始 createApp 与候选 createFrameworkApp 的是同一套断言。目标管理器、业务调用和更新器使用已有模拟对象；自动恢复隔离用例只创建虚构目标，不发起连接。测试监听系统分配的本地端口，不使用正式服务端口，不处理真实会话。

结果文件记录基准提交、候选版本、资源摘要、原始源码摘要、测试入口及退出码。目录与日志保留在仓库外，不自动清理。命令退出非零时不隐藏或跳过失败。

## 结果

两个入口共 30 项测试全部通过。覆盖：

- 原始路径、查询参数、重复键、JSON 原文与未知字段、错误文案、状态码及关键响应头。
- Host、Origin、CSRF、手机配对的拒绝顺序及目标隔离。
- 会话、问题回答、工作区、侧栏、桌面与定时任务适配的参数和调用次数。
- 文件 Range／HEAD、客户端取消、上游错误及短传输后的清理。
- SSE 初始事件、待处理请求、更新顺序、订阅释放与重复重连。
- 页面占用与目标、SSE 连接及手机登录的绑定。
- 静态文件压缩、缓存校验、允许列表及手机未配对资源边界。

30 项中也包含候选专属的 CSS 构建、未知 SSE 字段保留与预览 Cookie 隔离断言；并非每项都是双边差分。不将测试项数等同于接口数量或真实原生功能数。

完整 npm test 另通过 891 项 Node、74 项 Python，包含类型检查与构建。新增的是验收入口和文档，没有修改应用路由、安装或重启正式服务，预览仍运行上述应用提交。

## 限制

这是指定原始提交与指定构建的隔离协议证据。它不替代真实 SSH 业务操作、浏览器集成、实体设备、整体性能或原生接口升级后的重新核验。全量验收继续按[交付审计](framework-delivery-status.md)执行。
