# 目标完成状态的位置

## 行为

用户截图显示原生 complete 目标仍占据输入框上方。现在原生目标明确 complete 时隐藏操作栏，将“✓ 目标已完成”作为独立元数据放在完成时间对应的轮次之后。可展开查看目标原文、原生更新时间与用量。不改写助手正文，不标记整个会话完成，不调用 clear/set，不另建目标状态。

按原生 updatedAt 与轮次 startedAt 定位最近的先行轮次；后续聊天不改变位置。缺少可匹配的已加载轮次时放在消息区前方作为独立状态，不附在后续回复上。读取失败或历史未确认时不新增完成标记。仍以原生当前目标为准，原生清除或替换后不额外保存完成历史。此项不是完整目标历史存档功能。

视觉沿用系统字体与黑色文字。状态行无卡片边框；展开不增加管理按钮。键盘焦点保留黑色轮廓。原生依据沿用 [目标栏验收](verification-2026-10-23-native-goal-toolbar.md) 的 complete 状态与时间字段，以及用户本次截图。

## 验证

- npm test：469 项 Node、69 项 Python 通过。新增 complete 隐藏工具栏、定位旧轮次、后续消息隔离、缺失轮次、状态未确认与非完成状态回归。
- ego-browser 独立 4327 预览、全新状态目录，全部交互 API 模拟。完成状态下只有一个标记，位于原目标轮次和后续轮次之间；目标栏隐藏；未发出任何目标写请求。active/complete 切换能移除和恢复对应展示，无脚本异常。
- 桌面键盘 Enter 展开目标原文、时间、token 和耗时。iPhone 12/14 共用 390×844、DPR 3、5 触点，移动视口和触控模式生效；touchStart/touchEnd 折叠通过，无横向溢出。没有修改输入事件，未重测实体手机软键盘、中文候选窗和剪贴板。
- 未修改原生数据或真实业务目标；真实目标完成全链路未重测。浏览器任务空间与独立预览已关闭。
- 无新增网络请求、轮询或定时器。定位为已加载轮次数量的线性扫描，复用现有消息渲染与缓存失效流程。未做 CPU、内存基准。
