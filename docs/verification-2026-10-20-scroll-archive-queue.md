# 长会话直接定位与侧栏操作排队

## 调研与实现

- 对照现有 `docs/sidebar-parity-2026-10-18.md`、归档接口及归档延迟验收记录。原生归档沿用 thread/archive、运行/历史/后台任务检查、结果核对及桌面通知；没有修改原生引擎和数据。
- 消息容器原有 CSS smooth 使缓存、预览、完整内容和 ResizeObserver 的尾部定位触发多次动画。改为 auto，沿用既有跟随偏好和历史锚点；进入会话直接到末尾，向上阅读仍停止跟随。
- 前端全侧栏 pending 与后端 sidebarMutation 原先共同阻止连续操作。改为当前标签页的请求队列：不同目标可以继续提交；同目标禁用重复操作；原生写请求顺序执行，服务端保护保持不变。不新增原生任务或持久化调度器，不自动重放失败写入。
- 列表刷新在请求队列外进行；归档不禁用项目新建菜单、归档列表或其他会话菜单。撤销恢复也走同一请求队列。切换账号后的迟到结果不更新新账号，未执行的旧账号请求取消；连接断开时排队项执行前拒绝发送。
- 排队仅存在当前页面，刷新/关闭页面不承诺继续执行；已发出但结果未知的请求仍沿用现有核对机制。不同标签页仍遵守单入口操作约定。
