# 查看变更与原生撤销接口核验

## 实现范围

本轮用户要求加入“查看变更”和“撤销”。已实现查看变更。撤销尚未接入，不展示不可执行的操作按钮。

卡片标题提供“查看变更”，不必展开完整清单。窗口支持文件选择及前后导航。文件名优先显示，完整路径在内容区展示。同一文件的多次原生补丁按原顺序显示，状态及缺少内容明确提示。只渲染当前文件，不创建整轮所有补丁节点。关闭窗口销毁快照；切换会话或连接调用关闭入口。窗口明确显示“打开时快照”，不冒充工作区最终净差异。

复用原生 fileChange 记录、既有弹窗和控件样式。未新增网络接口、轮询、执行逻辑或依赖。没有修改 Codex 安装、配置、原生数据库或用户文件。

## 撤销调研结果

只读核验当前桌面版本 26.1016.62342（21477）的安装包及配置指定的原生二进制生成协议。导出的 ClientRequest 有 172 个请求方法，没有文件补丁撤销入口。

- `ThreadRevertParams` 明确说明只改变持久化会话历史，不回退本地文件。桌面内部 `thread/rollback` 同样用于会话历史操作，不能据此实现文件撤销。
- 截图对应的 `codex.unifiedDiff.revertChangesTooltip` 位于 `sites-end-resource-7244e15fbe89.js`。卡片通过桌面 Git worker 的 `apply-patch` 执行撤销及重新应用，使用原始 patch batches 和项目根目录。实现还处理非 Git 仓库、失败及部分成功。
- `.vite/build/worker.js` 分发 `apply-patch` 和 `apply-review-section-changes`。主进程 `main-JI9qDiXp.js` 通过内部 worker bus 转发；AppHost 创建及 MessagePort 绑定受受信任 Electron 页面校验。
- `src-CsH31EEu.js` 中桌面 Unix IPC 使用有限方法版本表和 `requestHandlers`。现有 owner/follower 分发未发现 Git worker 的补丁接口。
- `TurnDiffUpdatedNotification` 是轮次聚合差异通知，不是撤销接口；不能从通知名称推导历史净差异获取或撤销能力。

上述为静态接口和分发链核验，未执行真实撤销，也未证明所有未来或远程版本都不支持。当前没有核实到 RCM 可用的原生文件撤销入口。遵守 [项目边界](../AGENTS.md)，不复制内部 worker、不注入桌面、不用自建反向补丁或 git reset 补齐。撤销仍需在目标机器 Codex 桌面操作。
