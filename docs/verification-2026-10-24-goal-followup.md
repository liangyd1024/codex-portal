# 目标运行中的补充消息发送

## 原因与修改

截图中的“引导”进入普通消息发送流程，但此前 validateGoalDraft 和 prepareGoalSubmission 仍检查浏览器残留的 goalPending。运行中输入因此被误判为设置新目标，在调用引导接口前报“请等待当前轮次结束后设置目标”。

运行中输入现在绕过新目标准备，继续使用原有引导或排队接口。已确认有 active、paused 或 blocked 原生目标时，清理过期的本次设置目标标记。原生目标读取失败、目标完成或设置结果未确认时，不据此清理标记。未确认回执仍保留，不能用引导成功推断目标设置成功。

没有修改原生目标、后端目标设置保护、正文、草稿确认流程或权限策略。新目标仍按原流程设置。依据已有输入框目标验收记录，目标设置会自行启动执行，后续普通消息不能再次设置目标。

## 验证

- 定向 30 项测试通过，覆盖引导不调用目标接口、未确认回执保留、标记清理及会话隔离，以及既有原生目标与引导适配。
- npm test：478 项 Node、69 项 Python 测试通过。
- ego-browser 完整页面模拟：注入既有 API fixture，使用本次 app、composer、goal-submit 源码；其余模块和样式取自正式网页。通过调试上下文装配模块，没有修改服务文件、安全策略或原生数据。
- 开发端口已被其他项目占用，未停止服务或换端口。因此本次属于浏览器模拟，不是独立预览服务验收。
- 模拟已运行目标及残留 goalPending。渲染后标记清除；点击“引导”只产生一次 /steer；桌面普通发送走 /queue-add。所有补充发送均未调用 /goal，目标栏保持进行中。
- 模拟引导失败保留草稿，重试成功后清空。合成中文 composition / Enter 229 无新增写请求。全选、剪切、粘贴后文字保留。页面未记录 JavaScript 错误。
- 桌面 1480×747 及手机设备模拟截图已查看。iPhone 12/14 共用尺寸参数 390×844、DPR 3、mobile=true、5 个触点、coarse pointer，执行前核对生效。触控发送走 /steer，无页面横向溢出。
- 一次手机检查因等待 body 上的 mobile-layout 超时；该类实际位于 html。纠正断言后通过。未将该超时视为产品故障。
- 未向用户业务会话发送测试消息，未中断目标或任务。未实测实体手机、真实软键盘及输入法候选窗，也未执行本次真实原生写入端到端验收。

## 性能与范围

运行中发送直接返回目标准备步骤，不增加目标读取、设置请求或轮询。标记同步为常量判断，仅状态变化时保存一次选择。本次没有测量真实端到端延迟，不声称性能最优。视觉样式及布局未改。
