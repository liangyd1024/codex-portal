# 工作台浏览器部署检查

## 原因

此前模块单元测试使用本地导入，启动恢复测试替换了模块传输。它们不能证明浏览器能通过 HTTP 取得全部模块。部署只检查版本接口，没有执行前端。静态路由遗漏因此未被部署拦截。

上一修复已补充 HTTP 模块依赖图检查。本次把真实浏览器检查接入标准安装程序，手动安装与网页更新共用该检查。

## 行为

- 重启前准备 ego-browser 检查空间。浏览器不可用时不重启网页。
- 新版启动后先核对版本接口，再打开正式网页，禁用资源缓存及 Service Worker 缓存。
- 等待启动面板隐藏及入口模块执行完成，核对浏览器看到的版本，拒绝脚本、样式加载错误及未处理异常。
- 未通过检查时进入原网页回退流程，不写入新版本安装成功记录。
- 专用新标签页不点击控件。探针只放行 GET/HEAD fetch，阻止自动连接及其他写入请求；不模拟成功响应。
- 检查完成后关闭专用空间。不清理用户浏览器数据。

## 验证

- 新增 5 项回归：无浏览器、版本错误、初始化超时、模块与运行错误、只读请求保护、正式安装回退顺序及成功记录保护。
- 安装流程测试执行实际安装脚本的控制逻辑，替换文件系统与服务操作；模拟版本接口通过但浏览器失败，确认恢复旧网页并不写 installed.json。
- 真实浏览器读取当前正式网页通过。
- 仅在专用检查标签页阻断过程摘要模块，真实浏览器检查拒绝部署，单次约 22.5 秒。没有破坏正式服务资源。
- 首轮全量测试有 SSE 事件分流及文件监听两项异步测试失败。相关复核通过；第二轮完整测试 611 项 Node、70 项 Python 全部通过。
- 全量测试期间有其他会话修改过程摘要界面；本次仅提交部署检查涉及的文件。

检查只在部署时运行，无常驻浏览器轮询。单次 CLI 调用限制 45 秒，启动等待 20 秒，入口模块等待 15 秒。未测量 CPU、内存峰值，不声称性能最优。未修改布局和输入流程，未进行手机或真实软键盘验证。真实生产回退未人为触发；回退控制逻辑由隔离测试验证。

本记录随功能提交保存。正式部署结果待工作目录干净后补记。
