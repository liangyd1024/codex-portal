# 失败会话归档

## 问题与修改

原生会话在轮次失败后可以保持 `systemError`。旧归档检查仅接受 `idle` 和 `notLoaded`，因此已经结束的失败会话也会被拒绝。

归档检查现在读取最新五轮的原生摘要。`systemError` 必须有非空的终态历史，且通过后台命令、队列、目标及待处理请求检查，才能调用原生 `thread/archive`。未知状态仍拒绝。检查期间发生连接、账号或运行状态变化时，不执行归档。

状态无法确认时，错误信息区分会话状态、历史格式、轮次状态和空历史。连接诊断仅记录会话 ID、轮次 ID 和状态，不记录消息正文。跨入口写入冲突沿用明确的归属提示，不停止其他入口，不删除锁文件，不修改原生数据库，也不重发失败轮次。

## 验证

- 现场只读接口确认问题会话状态为 `systemError`，历史轮次均已结束。现场标识不写入仓库。
- `node --test test/sidebar-actions.test.mjs`：33 项通过。
- `npm test`：459 项 Node 测试和 69 项 Python 测试通过。
- 回归覆盖终态失败、空历史、未知状态、畸形记录、运行轮次、后台命令、队列、活动目标、待回答请求，以及检查期间连接、账号和活动变化。
- 既有写入冲突、归档超时核对和桌面通知失败测试通过。归档失败不会假报成功或自动重放。
- 成功路径仍只读一次会话状态和一次历史，未增加原生请求次数。历史限定五条并使用摘要；没有新增轮询。未测量真实网络延迟或宣称性能最优。

本次未修改浏览器布局、输入或前端代码。测试为接口模拟和现场只读核验；不把这些检查视为正式环境归档成功。部署结果另行记录。
