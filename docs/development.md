# 开发指南

[项目首页](../README.md) · [使用与运维](usage.md) · [协作约定](../AGENTS.md)

## 准备环境

使用 macOS、Node.js 22.12+、Python 3、Git 和可运行的 Codex。

```sh
npm ci --ignore-scripts
npm run doctor
npm run init
```

Codex 路径非默认时，为 `init` 添加 `--binary /absolute/path/to/codex`。
依赖安装不部署服务。运行数据和凭据保存在仓库外。

## 代码结构

| 目录 | 职责 |
| --- | --- |
| `src/web/` | React 界面、Zustand 状态和 TypeScript 前端服务 |
| `src/server/` | Fastify 应用、HTTP 路由和应用服务 |
| `lib/` | 原生 RPC、桌面 IPC、SSH 和系统适配 |
| `public/` | 公共样式、兼容入口和浏览器基础算法 |
| `shared/` | 前后端共用的纯数据逻辑 |
| `scripts/` | 构建、启动、数据读取、安装和维护工具 |
| `test/` | 纳入版本管理的 Node.js、Python 测试及隔离夹具 |
| `acceptance/` | 本地验收资料，由 Git 忽略 |

浏览器通过 HTTP/JSON 和 SSE 连接 RCM。RCM 通过适配层访问目标机器。
Codex 负责会话执行和任务调度。RCM 配置及缓存不替代原生业务数据。

## 启动预览

```sh
npm run typecheck
npm run build
npm run start:preview
```

打开 [开发预览](http://127.0.0.1:4327)。修改源码后重新构建。
启动器创建独立状态目录。需要指定目录时，设置绝对路径 `RCM_PREVIEW_ROOT`。
新目录必须为空；复用目录必须带有启动器生成的所有权标记。

预览连接真实目标。只操作专用测试会话，不操作正在使用的业务会话。
预览不提供正式网页更新，也不启动自动登录恢复。

手机预览使用独立端口和配对数据：

```sh
npm run start:preview -- --mobile
```

| 入口 | 正式服务 | 开发预览 |
| --- | --- | --- |
| 本机网页 | 4317 | 4327 |
| 手机本地代理 | 4318 | 4338 |
| 局域网 HTTPS | 4319 | 4339 |

端口占用时先查原因，不自动换端口或停止其他进程。
手机预览需单独信任证书并配对。它不修改正式入口的 Tailscale 转发。

## 原生适配边界

- 新能力先核实协议，再验证实际调用。schema 中存在方法不代表运行时支持。
- 原生接口不可用时，显示限制并保留草稿。不得修改 Codex 安装文件或原生存储来绕过限制。
- 会话身份使用连接 ID 和原生会话 ID。标题仅用于展示。
- 迟到响应不能覆盖已切换的连接、会话或草稿。
- 发送结果未知时，先核对原生记录。不要自动重放。
- 普通断开只关闭当前入口的传输。停止目标引擎使用独立的维护流程。

### 会话引用

普通网页会话通过 RCM 只读 MCP 适配读取引用。
底层使用原生 `thread/read` 和 `thread/items/list`。
被引用会话不恢复、不订阅，也不接管。

引用限同一目标连接，每条消息最多选择 20 个会话。
授权按发起会话和所选引用 ID 校验。
分页返回原文，超出读取限额时明确报错。
旧会话需要启用工具时，仅在空闲且可安全释放后恢复同一 ID。

### 定时任务

任务列表读取 Codex 原生数据。创建、修改和删除通过桌面托管的管理会话完成。
不要增加独立任务副本、编辑表单或调度器。
桌面关闭或协议不兼容时，保留草稿并提示恢复。
原始工具结果是变更依据；消息回执不能证明任务已变更。

### 尚未支持的能力

输入预测尚无已验证可达的完整原生入口。不得将接口声明或内部类名标为可用能力。
桌面项目列表同步、跨入口会话引用及 SSH 桌面任务管理仍需按目标版本验证。
不要把本机结果外推到其他目标或版本。

## 验证

行为变更先运行相关测试，交付前运行完整测试：

```sh
npm test
```

入口先构建，再执行 Node.js 和 Python 测试。
单独运行 Node.js 测试时可使用：

```sh
node --experimental-strip-types --test test/goal-submit.test.mjs
```

将文件名换成相关测试。单项测试不能替代类型检查或完整回归。
测试继续使用独立临时目录。目录路径会输出，清理由使用者处理。

### 验收资料

`docs/` 只放可持续维护的使用和开发说明。验收资料统一放在根目录 `acceptance/`：

| 子目录 | 内容 |
| --- | --- |
| `reports/` | 验收结论与未验证项 |
| `screenshots/` | 桌面和手机截图 |
| `data/` | 请求记录、性能采样和检查结果 |
| `logs/` | 验收命令输出 |
| `scripts/` | 一次性验证脚本 |

按需创建子目录。整个目录由 Git 忽略，不使用 `git add -f` 提交。
可复用的回归测试移入 `test/`，测试夹具移入 `test/fixtures/`，并提交 Git。
构建输出仍在 `.framework-build/`。测试结果、覆盖率和本地日志目录也由 Git 忽略。
现有测试脚本的系统临时目录保持不变，不为归档资料修改测试运行逻辑。
含真实账号、凭据或部署信息的资料仍放在仓库外。

`.gitignore` 不会停止跟踪已有文件。迁移已有验收资料时，保留本地文件，并提交原跟踪路径的移除。

需要比较旧 HTTP 实现与新构建时，执行：

```sh
node scripts/verify-framework-baseline.mjs <基准提交> /absolute/path/to/build
```

构建目录必须包含 `manifest.json`。此检查使用隔离样本，不替代真实原生接口验证。

### 界面与性能

- 检查默认、悬停、焦点、禁用、进行中、失败和断连状态。
- 检查中文输入、全选、剪切粘贴、草稿恢复和误发送。
- 手机检查启用移动视口、设备像素比和触控模拟。保留 390px 竖屏基线。
- 按改动补充横屏和短高度场景。记录设备参数。
- 实体键盘、候选窗、选区手柄和系统剪贴板需单独实测。
- 性能对比使用相同版本条件、样本和设备参数。记录耗时、请求数和资源开销。
- 区分模拟、真实服务和实体设备结果。未测项目不得标为通过。

## 发布

构建会写入新目录，并记录提交与产物摘要。
`npm test` 成功后生成测试凭据。单独构建不能替代部署验证。
安装器先准备完整版本，再切换网页服务。健康检查失败时恢复旧版本。

发布步骤见[安装指定版本与回退](usage.md#安装指定版本与回退)。
纯文档修改不运行应用测试，也不部署服务。

公开发布前，分别审计当前文件、Git 历史、截图和远端资产。
删除当前日志不等于清除 Git 历史或远端 Release。历史改写和远端删除需单独授权。
空白 Mac 安装和自定义原生数据目录仍需独立验证，不能由已有环境升级结果推断。

## 文档写法

参考 [ASD-STE100](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf) 的写作原则。
中文文档借鉴其方法，不宣称符合完整英文标准。

- 每句表达一个动作或事实。先写条件，再写动作。
- 同一概念使用同一术语。使用主动句和常用词。
- 操作使用编号步骤。比较使用表格。
- 保留命令、前置条件、失败处理和能力限制。
- 删除重复说明、操作流水和过期状态。
- URL 使用显式 Markdown 链接。不要把裸地址直接夹在加粗标记中。
- `docs/` 保存当前说明。验收过程放在本地 `acceptance/`，不提交。
- 许可证、第三方声明和必要归属信息保持原文。
