# 当前候选问题回答集成复核

## 版本与方法

本轮正式 4317 版本接口仍为 `227dbfe93ee88718c2437f7b7c7b119570a720a6`。候选为 `7eb6eb350d6bef129d962df833d61c6aa23db7ef`，资源为 `44ed4d81fdeecb3addb105017d0a55c3a3e94e45607ff420a6e8a84f8cde203b`。使用与当前候选资源一致的静态隔离入口和上述正式提交导出的基准。

桌面使用 `1480×747`、DPR 2、触控关闭。iPhone 12 模式包括 `390×844`、`844×390`、`390×480`，DPR 3、触控开启。逐样本检查实际视口、DPR 和触控值。保留正常扩展和 React 调试回调，手机按钮通过触控事件操作。

虚构 API 截获全部回答请求，不操作真实待处理问题。仅重置本轮隔离入口的虚构问题草稿键，没有清理整个浏览器或正式页面存储。

## 原生问题卡片

四种视口共 56 个样本、28 组配对一致。覆盖初态、选择与中文回答、断线禁用、离线折叠、恢复连接、卡片重建保留答案，以及提交完成。逐节点比较文案、类名、字段值、选中、禁用、隐藏、可访问属性、几何位置、计算样式和焦点；同时比较草稿及完整写请求。

每个流程只发送一次模拟原生回答，路径为测试请求的 respond 接口，两个答案分别为所选项与输入文本。完成后问题卡片消失。实际设备参数正确，无页面错误或横向溢出。

## 异步问题

四种视口共 96 个样本、48 组配对一致。覆盖必填提示、选项与中文文本、自定义文本覆盖选项、折叠与展开、跳过与恢复、组合输入期间禁止提交、接口失败保留、重试等待禁用和成功提交。

组合输入阶段没有回答请求。每个流程的失败与重试请求正文完全相同，保留异步问题的 turnId、itemId 和答案对象。逐节点状态、计算样式、几何、焦点、草稿与请求均一致，无页面错误或横向溢出。

## 提交期间切换会话

四种视口追加 40 个样本、20 组配对一致。原生回答先失败，保留答案后重试；将重试响应挂起，切换到另一虚构会话，输入独立草稿，再释放旧回答。确认旧响应正文已经被页面读取，且后续状态读取完成后，新会话标题、独立草稿和输入框焦点仍保持。失败与重试正文完全相同，没有重复提交。

初轮仅等待后续状态请求，虽然 20 组结果一致，但不能单凭该信号排除其他刷新。随后在模拟 fetch 的响应 text 方法加入只读消费标记，完整复验四种视口。此处只计后一次的 40 个样本，不将初轮重复计数。未修改页面业务处理器或调试回调。

本报告共 192 个有效样本、96 组配对，均一致。

本轮没有产品代码修改或服务重启，未重复执行应用测试。候选既有完整回归为 884 项 Node、74 项 Python，类型检查与构建已通过；本报告不扩大该证据范围。原始脚本和结果保存在仓库外。整体交付缺口仍见[当前交付审计](framework-delivery-status.md)，不能仅凭此专项标记全量通过。
