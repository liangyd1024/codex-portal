# 专用引擎文件句柄额度

实现版本见本文件首次提交的 Git 历史。

## 原因与范围

真实服务出现 `Too many open files (os error 24)`，影响技能读取和命令创建。只读快照为 236 个句柄，其中 145 个管道、62 个普通文件、其余为套接字及事件队列；52 个直接工具子进程。引擎直接启动的 Python 工具实际软限制为 256，硬限制无限；launchd 默认软限制也是 256，专用服务未配置资源额度。历史快照为 240 个句柄，本次未见单调增长，不能据此认定原生引擎泄漏。

RCM 恢复已接管会话的原生订阅；单会话交还才退订。已设置的卸载等待仅适用于无订阅且无活动会话。此次不自动退订、结束工具或改变原生会话生命周期，避免丢失正在使用的工具状态。

## 修改

新建专用 launchd 服务配置增加 `SoftResourceLimits.NumberOfFiles=4096`。依据本机 `launchd.plist` 手册，该字段设置进程资源限制。不更改硬限制、全局限制或 Codex 安装及数据。已运行引擎不改写配置、不重启。README 说明生效条件与泄漏排查边界。

## 验证

- 相关 Python 测试 5 项通过。覆盖新启动配置、已有引擎不重启且 plist 不改写、维护失败边界。
- `npm test`：631 项 Node、72 项 Python 全部通过。`git diff --check` 通过。
- 独立临时 launchd 测试服务使用相同软限制，实际读取到 4096，硬限制未改变；同时打开 512 个句柄成功，耗时 8.21 ms，随后全部关闭。测试服务已卸载，临时文件保留。
- 修改不增加轮询、网络请求或常驻进程，只改变新进程额度；额度不会预先打开文件。未做长期 CPU、内存或实际并发任务压测，不声称性能最优。

## 未完成的生效验证

代码提交 `f53bdd2` 已推送并按标准安装流程部署正式网页。安装退出码 0，版本健康检查和 ego-browser 工作台加载检查通过。没有修改或重启运行中的原生引擎。

网页部署不等于运行中的原生引擎额度生效。现有引擎仍需另行明确重启授权，并通过会话、目标、后台命令、队列及其他入口维护检查。未重启原生引擎，未证明长期运行不存在资源泄漏。
