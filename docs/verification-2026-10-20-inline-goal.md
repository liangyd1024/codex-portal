# 输入框直接设置目标

## 交互与原生行为

目标不再打开表单，点击 ＋ → 目标显示“目标 ×”，使用当前输入框文字；发送不携带 tokenBudget。取消选择保留草稿；新建会话也支持先选择目标。后续普通消息不会重设目标，重新选择目标才用新输入更新。暂停/继续/完成移至 ＋ 菜单，实际目标状态仍来自原生引擎。

真实测试发现：thread/goal/set 的 active 状态本身触发原生执行。原计划的“设置后再发送普通消息”会得到 TURN_ACTIVE，因此最终实现为文字目标仅设置原生目标，不额外 turn/start，也不伪造用户消息。附件使用原生当前轮次 steer，已空闲时使用正常消息；这部分完成模拟测试，未重新向模型上传真实图片。模型和执行仍由原生目标能力控制。

仅保存浏览器的待提交选择及结果未确认回执，不建立目标副本。请求前保存回执，超时重试先读取原生状态；匹配则不重复写入，不匹配则保留草稿并要求核对。成功后后续补充走原有消息流程。失败、会话切换不覆盖其他草稿。已有后端预算接口保留兼容，不自动更改历史目标的预算。
