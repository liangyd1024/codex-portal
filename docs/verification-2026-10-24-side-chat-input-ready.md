# 侧聊创建期间允许输入

基线 `e214009`。实现版本为本文件首次提交所在提交。

## 原因与修改

依据用户截图、现有侧聊原生接口与交互核验记录排查。侧栏打开后立即渲染输入框，但 localContext.ready 要求原生侧聊 ID 已返回。服务端依次执行 thread/read 和 thread/fork；原生 fork 超时上限为 60 秒。旧版 input.disabled 绑定该 ready，导致整个请求期间不能输入，open 中的自动 focus 也无效。本次没有测量用户实际会话中两个原生调用各自的耗时，不能认定 fork 内部的具体瓶颈。

输入框改为仅在提交消息期间禁用。创建中、创建失败、连接中断和过期时允许编辑本地文字草稿。发送、模型及其他需要原生能力的操作仍沿用原有就绪检查。创建状态提示可以先输入。不改变原生 fork、权限、消息内容、请求去重或提交语义，不自动发送草稿，不新增请求、缓存或轮询。

## 验证

- 完整 npm test：661 项 Node、72 项 Python 通过。新增创建期间可编辑但不可发送、创建失败及过期输入、创建去重和文字保留回归；保留重复发送与迟到响应测试。
- ego-browser 使用已有 4327 服务提供静态依赖，在独立隔离文档注入本次组件代码和公共样式。端口已有其他预览进程，未停止该进程或改变端口；没有启动本次专属完整预览。业务 API 全部模拟，没有操作真实任务。
- 故意悬置创建响应：侧栏同步打开约 7.3ms，输入框可编辑且自动聚焦，发送禁用，只有一个创建请求。此数字是单次组件模拟测量，不代表真实原生创建耗时。
- 桌面 1440×1000：模拟失败后中文草稿保留、可继续编辑；Escape 关闭后重开恢复草稿与焦点，无横向溢出。目视查看桌面截图，公共输入卡片黑色边框保持不变。本次未修改 CSS。
- iPhone 12 参数：390×844、DPR 3、mobile、5 点触控、coarse pointer 均在同一浏览器调用内核对。触控聚焦后输入中文，Enter 换行；创建成功后内容保持一致，发送调用数为 0，无横向溢出。合成中文 composition 事件不误发送。目视查看有效设备模式截图。
- 初次设备设置跨工具调用失效，未将该截图计为手机验证；随后在单次调用内重新设置并核对，完成上述测试。
- 全选剪切后文本为空，但自动化系统粘贴未恢复文字，此项未通过；后续通过 insertText 和 fill 验证输入及草稿。实体手机、真实软键盘、系统剪贴菜单和真实中文候选窗未实测。
- 未重新操作 Codex 桌面侧聊，也未在真实模型侧聊发送测试轮次。未测主线程压力、CPU 或内存，不声称整体性能最优。
