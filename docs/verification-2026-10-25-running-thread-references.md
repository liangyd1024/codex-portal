# 运行中引导消息的会话引用修复

基线：`0a3ee2a`。功能提交见本文件后续版本记录。

## 问题与修复

运行中的会话选择引用后，前端将其与首次启动目标一起拦截。服务端也拒绝所有带引用的引导消息。发送辅助函数还会丢弃引用 ID。

现在“引导”保留用户原文和引用 ID，通过原生 `turn/steer.additionalContext` 提交引用元数据。沿用已有只读引用工具和授权范围。不改写目标，不生成额外轮次，不替换用户消息。

仅允许已加载且引用工具已连接的会话。若工具未启用，明确提示任务结束后重试，不调用 unsubscribe 或 resume。协议能力未确认时保留草稿。原生轮次 ID 校验仍有效，准备过程中轮次结束不自动改为新轮次或重发。

排队发送引用、首次启动目标并携带引用仍不支持；提示分开说明，不再要求运行中的普通引导等待目标完成。

## 验证范围

- 本机实际 Codex 二进制生成的实验协议确认 `turn/steer.additionalContext` 存在。协议检查新增独立能力，并更新缓存策略版本。
- 回归测试覆盖引用 ID 透传、原文和引用上下文分离、缺少协议字段、未核实能力、运行中仅授权已连接工具，以及无工具时不卸载任务。
- 单个引用的模拟调用检查确认仅查询一次引用工具状态；不新增轮询、目标设置或会话重载。引用准备沿用现有被动详情读取和授权写入。未测量真实网络延迟或 CPU、内存性能，不声称性能最优。
- 用户要求保留占用 4327 的其他预览，跳过本次预览验证。未对本次修改执行桌面、移动设备模式、触控、中文输入法或真实模型读取引用的端到端验收。
- 未操作用户正在运行的业务会话。

完整测试与正式部署结果在版本记录中补充。正式网页加载检查不代表实际模型端到端验证。
