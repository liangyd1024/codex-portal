## 服务端结束流后的重连

四种视口、两版各三轮断流恢复，共二十四轮、十二对完整阶段记录一致。断开和恢复验收流的手机按钮使用触控事件，未直接调用应用 onerror／onopen。每轮原生事件依次出现 open → error → open；服务端打开次数依次为 2、3、4，活动流始终为 1，等待流为 0。

恢复后的输入与发送均可用，中文草稿和原助手正文节点保持，标题一致，无页面异常和横向溢出。此组验证原生 EventSource 的隔离重连，不扩大为真实 SSH、系统断网或手机 HTTPS 链路。

## 浏览器模拟离线但原流保持连接

四种视口、两版共八条流程一致。离线前、离线中、恢复后依次从隔离服务推送序号 1、2、3。离线时新 HTTP 请求报 TypeError，但已有 SSE 仍收到序号 2；恢复在线后 HTTP 返回 200，并收到序号 3。

两版仍复现同一页面状态问题：恢复在线后输入与发送禁用，点击页面刷新后仍禁用。整页重载后重新建立流，输入恢复，中文草稿完整。所有离线模拟均在 finally 中恢复，测试结束清空模拟草稿。没有页面异常。

这证明的是页面传输状态恢复缺口，而不是事件流停止送达。该现象在 master 基准同样存在，本轮没有单独改变候选行为，不能标为离线恢复成功。整页重载的恢复证据不代表实体手机、真实网络切换或所有断线原因均可恢复。
