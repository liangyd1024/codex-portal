# 新建会话页面协调迁移

对照正式源码及 4317 的 `227dbfe`。将新建草稿设置保存、项目选择、打开和关闭新建页四个函数迁入 `src/web/services/new-chat-page.ts`。原创建与发送服务、草稿键、项目根目录规则、CSS 和组件结构不变。

输入区仍在原会话和新建页之间移动同一个节点。打开时保存原草稿并恢复新建草稿；关闭时保存新建草稿，按原 restore 参数决定是否恢复原会话输入与延迟上报。打开状态通过同步 getter／setter 连接现有变量，布局与模型协调器使用延迟调用，避免初始化顺序变化。

四个函数转译后的运行 token 对比一致；比较时归一化打开状态访问器和动态 UI getter。初次类型检查发现已匹配项目根目录的值仍被推断可能为空，补充与匹配条件一致的类型约束后通过。初次完整测试因该类型错误在构建前停止；修正后重新执行完整验证。旧构建的临时静态入口未用于浏览器验收，已停止。

新增五项行为测试覆盖：打开时节点复用与焦点／渲染顺序；关闭时保存和恢复草稿及延迟上报；restore=false 不覆盖输入；项目选择优先级和无效根目录回退；创建中拒绝再次打开及存储失败提示。类型检查、867 项 Node／74 项 Python 测试及构建通过。

桌面 1480×747／DPR 2，以及 iPhone 12 参数 390×844、844×390、390×480／DPR 3／触控，新建页往返流程共 56 个样本、28 对状态一致。比较新旧草稿、模型和思考档位选项／值／禁用状态、输入区所在容器、焦点、创建和发送请求体；输入区、输入框和模型选择节点始终保持原身份，无页面错误或横向溢出。手机使用触控。

首轮横屏在基准上遇到搜索刷新和目标定位冲突，尚未进入新建页。检查实际视口、抽屉和目标矩形后，增加等待搜索请求完成再聚焦和触控；保留桌面及竖屏结果，只补跑横屏和短高度。原始失败保留，没有为测试改动产品布局或搜索策略。

带附件创建的普通拒绝与结果未知两种场景，在同一四种视口追加 80 个样本、40 对状态一致。覆盖失败保留、重复提交保护、刷新后恢复、明确重试、成功发送、重新打开和关闭。比较错误／重试／关闭控件的计算样式、矩形、文案、隐藏和禁用状态、焦点、草稿、附件及完整创建／发送请求体。无页面异常或横向溢出。所有创建与发送由隔离夹具处理，没有写入真实会话。真实预览结果另行补录。整体迁移、全业务集成与资源性能门槛仍未完成。

本轮没有新增网络请求或刷新调度，移动输入区仍沿用原节点。运行算法一致和节点复用是限定保真证据，不代表整体性能已通过；首屏资源差异仍需解决。
