# 当前任务系统通知与扩展启动提示修复

## 范围与结论

用户反馈任务完成后没有系统弹窗；确认通知已开启且之前收到过。用户明确要求不补发历史遗漏、不增加自动重试，仅检查当前功能。此前确认的扩展启动提示优化同批完成。

未取得故障发生时用户浏览器的投递日志或系统通知设置，不能断言单一根因。已确认以下实现问题和兼容性改进：

- 通知开关原来仅在页面初始化读取；其他标签页开启通知后，当前页变量仍可为 false，从而跳过新完成事件。浏览器隔离测试已验证修复后能立即投递。
- 桌面原路径使用 `new Notification`，依赖 onshow/onerror 回调确认；本轮将支持 Service Worker 的桌面浏览器统一使用 `showNotification`。成功表示平台接受提交，不等于操作系统一定弹出横幅。
- 原先有积压 SSE 回放和连接恢复后重新发布完成记录两条补发路径。本轮均阻止历史完成通知：服务端停止发送积压通知，恢复记录不作为新完成事件广播；会话仍通过正常历史读取同步。浏览器也忽略旧回放格式，避免旧页面在重启时收到补发。没有删除原生记录或旧通知存储。
- 当前页面对相同通知只尝试一次；原有持久成功去重与 Web Lock 保留。失败不确认送达，不自动重试；后续新任务独立通知。手工“测试通知”保留。
- 通知偏好在 storage 和 focus 时同步。用户权限被拒绝或未开启时不发送；不自动申请或绕过浏览器权限。

## 扩展提示

`cua_repl` 等扩展 starting、ready、cancelled、failed 不再占用会话正文。启动失败原文进入有界连接诊断，并标记 diagnosticOnly，保留扩展名与会话标识。真实工具调用失败仍原样转发和显示，不修改原生工具初始化、任务执行或全局配置。

之前的浏览器复现确认：提示本身不禁用发送；扩展就绪后，尚未返回的发送请求仍显示“正在发送”。因此隐藏横幅不代表修复首次发送等待。本轮没有声称解决引擎初始化耗时。
