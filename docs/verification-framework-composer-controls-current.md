# 当前候选输入工具菜单复核

## 基准与范围

2026-10-25 重新核验正式 4317 为 `227dbfe93ee88718c2437f7b7c7b119570a720a6`，预览 4327 为 `accb11f2cfe0e6c1e6563de1560c86540978c4ba`。重新 fetch 后 `origin/master` 为 `0a3ee2ac8c97cafa89870d78323cf0dfc2f3692e`，相对正式提交仅有部署记录的四行文档差异。

本轮使用正式提交导出的静态源码与实际预览的干净构建；候选资源为 `0e4887c7d29f468a80e30e3f66cadc134469600cdab6c2ee7e1f476f801c1ec7`。没有使用已撤回的状态合并试验资源。

操作在同一个 Ego Lite Chromium 空间完成，正常 React 调试回调保持启用。接口与事件来自隔离夹具，测试内容均为虚构数据，没有发送真实原生业务操作。桌面参数为 1480×747、DPR 2、无触控；iPhone 12 模式为 390×844、844×390 和 390×480，DPR 3、触控开启。导航前后设置设备参数，每个样本记录实际视口及触控状态。

## 操作与比较

共 168 个样本、84 组新旧配对。覆盖初始状态、打开菜单、方向键进入、Home／End 导航、Escape 返回、计划选择和取消、目标选择和取消、计划与目标相互替换、轮次运行时禁用、断开与恢复。每次计划／目标操作后增加重新打开菜单的检查，共 24 组重新打开对照。结束时清空虚构输入草稿。

比较节点文案、可访问名称、标题、模式、禁用与展开状态、几何尺寸、字体、颜色、背景、边框、焦点轮廓、实际焦点、草稿与存储、写请求、页面异常及横向溢出。另记录每个节点的 `checkVisibility()` 和 `:hover`，不再以非零矩形推定关闭菜单的后代可见。

## 结果

73 组完整一致；11 组仅计划或目标按钮的计算背景色不同，差异节点在两版中的 `checkVisibility()` 均为 false。样本保留了不同的过渡透明度值，没有删除或将它们改写为透明色。其他被比较字段均一致。

24 组重新打开菜单的节点状态和样式全部一致。该证据支持本轮范围内没有可见菜单样式差异；不推定浏览器内部具体冻结或恢复样式的原因。四种视口均没有页面异常或横向溢出。

这次对照使用实际候选，不能回填[先前试验](verification-framework-composer-batch-experiment.md)缺失的可见性证据，也不将其 20 组原始差异改写为通过。先前试验代码继续保持撤回。

本轮没有产品代码修改、构建或服务重启，因此未重复执行应用测试。现有完整回归、性能限制及剩余范围见[交付审计](framework-delivery-status.md)。这项菜单验证不代表实体 iPhone 系统输入、全部原生业务或整体性能通过。原始脚本、完整状态样本及比较结果保存在仓库外。
