# 发送反馈验收

## 问题与修改

运行中追加指令调用原生 `turn/steer`。接口返回 `turnId`，原页面只有在返回完整 `turn` 时才补显示用户消息，因此追加内容需要等待后续历史同步。

发送前新增页面内的发送回执。立即显示原输入与“正在发送”；原生响应后显示“已发送，正在同步会话”。新的原生用户消息到达后移除回执。回执不写入原生历史，也不写入历史缓存。按连接、会话、轮次及新消息身份匹配，避免旧的同文消息误消除本次回执。重复发送相同文本需要分别收到新消息。

明确拒绝时显示失败；断网或未知结果显示待确认。草稿保留，不自动重发。发送准备阶段失败不显示为已发送。此修改优化页面反馈，不改变原生任务调度或执行速度。回执仅保存在当前页面内存，重载后以原生历史为准。

## 验证

- 单元测试覆盖仅返回 `turnId`、HTTP 慢响应前的可见状态、事件早于 HTTP、重复同文消息、跨连接会话隔离、失败和未知结果、图片内容保留。
- 从暂存树导出独立目录运行 `npm test`：409 项 Node 测试和 69 项 Python 测试通过。该测试不包含其他会话的未提交改动。
- 使用 ego-browser（ego-lite），在已有开发预览加载实际页面，并注入全接口模拟数据。未向真实引擎发送消息。
- iPhone 12/14 共用尺寸：390×844，DPR 3，移动模式及触控模拟启用。触控发送运行中追加要求，主动挂起 HTTP。内容显示“正在发送”，草稿保持。释放为仅含 `turnId` 的响应后，显示已发送且清空原草稿。随后模拟原生事件，只保留一条消息。无页面横向溢出或浏览器脚本错误。
- iPhone 17：402×874，DPR 3，移动模式及触控模拟。普通发送挂起 HTTP，点击到 DOM 回执插入单次测量为 11 ms；此值不是跨设备性能保证。响应后只保留一条原生消息。
- 桌面 1440×900：模拟网络断开，显示发送结果待确认，保留中文草稿，无横向溢出。
- 页面验收使用共享工作区预览，包含其他会话正在开发的改动；本次提交只包含发送回执修改。未重启或停止他人的预览服务。
