# 框架迁移统一交付记录

本页是纠偏后的唯一交付入口。完整应用层候选已进入统一验收，仍有性能差异及手机验证待完成，不能宣称全量验收通过、合并或正式上线。历史报告保留作追溯，不与本轮结果拼接。[历史持续记录](verification-framework-parity.md)。

## 目标与执行顺序

完整迁移 RCM 前后端应用层到 React、TypeScript、Zustand、Vite 和 Node.js、TypeScript、Fastify。网页与手机的功能、文案、样式、布局和交互不变。保留原 CSS、存储格式、连接 ID、未知原生字段和已核实的 Codex 接口。

在既有 `refactor/framework-migration` 分支及独立 worktree 连续完成实现。期间仅执行必要针对性回归，不为小模块重复浏览器测试、重启预览或新增阶段报告。全部实现后执行类型检查、完整 npm test、构建，冻结完整候选，再统一更新 4327／4338／4339。正式 4317／4318／4319、master、原生会话与引擎保持运行，不合并或正式部署。

统一验收重新读取实际 4317 与最新 master；先桌面，再 iPhone 390×844、DPR 3、触控，以及 844×390 横屏和 390×480 短高度。使用已授权 ego-lite。差异按基准修复，仅复验受影响范围。性能先定位原因再优化；不以提交次数推导性能。SSH 诊断有界，外部阻塞不停止其他工作。实体软键盘、候选窗、系统选区与剪贴板须实测，否则保留未验证。

## 本轮检查结果

- 类型检查已通过；首轮完整构建成功。
- 首轮完整 Node 回归为 909 项，904 通过、5 失败。4 项来自旧源码截取测试，已改为直接验证输入策略函数；1 项为 HTTPS fixture 未等待 Fastify 就绪，已补充正确生命周期。对应 10 项针对性复验通过。首轮因 Node 失败未执行后续 Python，不记作完整通过。
- 项目、侧栏、读取合并与剪贴板针对性 70 项通过；其余本轮针对性结果仅作开发证据，不代替最终 npm test。
- 此前轮次测试固定 30 ms 等待已改为受控计时器，保留原断言；首轮完整回归的轮次与文件监听检查通过。历史失败仍保留追溯。
- 第二轮完整 npm test 通过：909 项 Node、74 项 Python，包含严格类型检查和构建。资源指纹为 `faf4f912adca455a4dca8b90d1a378643fca34e4c25106d0e2a029d7edd68e36`。干净提交与 Node 22.12 的完整回归均通过，构建指纹一致。预览统一更新后开展同候选对照。

- `7b82f4d` 的桌面对照已覆盖输入、草稿、附件、目标、计划、排队、审批、侧栏、维护、流式消息、历史、侧聊、文件、容量重试、批注、轮次导航、通知模拟、交还和设置。功能采集大部分一致；发送按钮过渡色及备份样本缓存差异仍需定向核实，不能记为全部通过。
- 同版本 HTTP 差分 30 项、真实只读 HTTP／HTTPS 检查及本机版本、状态、模型、项目读取完成。真实 SSH 身份检查在 15 秒超时，未继续循环重试。
- 启动性能发现候选脚本耗时高于基准。CPU 采样定位到内容未变化时的重复同步状态发布。已对控件理由、运行提示、容量重试、交还及批注增加等值检查；真正变化仍同步更新。优化后完整 909 项 Node、74 项 Python 回归通过。单次四组交替样本中，候选脚本耗时从约 77–88 ms 变为约 74–78 ms；同期基准常见约 59–60 ms，仍未达到性能验收要求。这不是端到端提速结论。
- 上述浏览器结果属于指定候选的开发与验收证据。优化候选不得直接继承此前候选的全量通过结论。真实日志及完整采样留在仓库外。
