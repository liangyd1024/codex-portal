## 性能恢复执行记录

以下为源码整合后的新实验，不覆盖下文冻结候选的功能证据。用户授权直接使用有扩展的 ego-lite；未改动日常扩展和登录状态。

定位确认启动流程主动读取 CSRF 与并发写请求内部读取发生重叠。应用客户端现仅合并同一目标、同一客户端中尚未完成的默认令牌 GET；完成或失败后移除，不缓存完成结果，不合并写请求，带显式请求选项的读取独立执行。首次仅合并写请求内部读取的实验无效，已修正为两条路径共用读取。

独立静态生产构建对照：桌面 1480×747、DPR 2，以及 iPhone 12 的 390×844、DPR 3、触控，各比较一次。请求总数由 16 降至 15，CSRF GET 由 2 降至 1；其余请求在规范化随机 viewId 后完全一致。标题和设备参数相同，无页面异常及横向溢出。此证据证明减少重复请求，不证明首屏普遍提速。构建仅用于隔离模拟，不替换真实预览或正式服务。修正后类型检查、生产构建、完整 922 项 Node 与 74 项 Python 测试通过；新增测试覆盖并发写、失败重试、客户端隔离、完成后重读、主动读取与写请求重叠，以及显式传输选项独立执行。

扩展环境下的 CPU 定位仍显示应用初始化成本增加，不能将全部差值归因于扩展。高频采样中，桌面应用归属样本约 86.46→100.28 ms，手机约 80.99→103.36 ms；各一次且含采样开销，仅用于定位，不作为验收时间。工具输出跟随尾部的 scrollHeight 读取与输入尺寸读取是后续定位线索，尚未证明可安全减少，也未改动滚动算法。性能不标为通过。
