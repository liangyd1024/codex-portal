# Ally 会话历史读取故障修复

## 原因与修复

用户截图中的独立验收会话 `01a15752-863b-7820-ba99-4eeea23de0cb` 在 Ally 正式网页的详情和历史接口均返回 HTTP 502，错误为 `unable to open database file`。

只读检查确认 `state_5.sqlite` 和 RCM 自身输出日志可查询；`thread_history_1.sqlite` 文件存在，但没有 WAL/SHM 配套文件，执行 SQLite 只读查询失败。没有删除或改写原生文件来人为复现或修复。

通过正在运行的原生服务验证 `thread/turns/list`，参数为 `limit=5`、`sortDirection=desc`、`itemsView=full`，完整返回该会话的用户消息与助手回复。请求前后已加载会话列表相同，未调用 resume、subscribe、turn/start。

改动：

- 快照打开失败时回退到原生完整历史读取。其他错误和原生读取失败仍暴露，不能当作空历史成功。
- 原生分页游标使用独立前缀，后续页固定沿用原生接口；已有快照分页失败时要求刷新，不将 SQLite 序号传给原生接口。
- 保留原始消息和 RCM 自身命令输出日志的增量、压缩及预览契约。
- 核对异步请求所属连接，丢弃连接变化后返回的历史。
- 正常快照读取继续保持被动读取，不增加原生请求。
