# 会话切换读取优化

基线提交：`17094c0`。实现提交见本文件所在实现提交及后续部署记录。

沿用既有正文、原生历史读取和滚动流程。切换时不再串行等待 IndexedDB 恢复；网络读取与恢复并行启动。缓存未命中时，恢复读取从两次减为一次。只在当前选择、连接版本未变且尚无网络详情或读取错误时应用缓存。缓存不授予控制权，不覆盖最新正文，不隐藏网络失败。

原生交互依据：沿用已有正文完整性及会话切换验收，见[性能优化验收](verification-2026-10-22-performance-optimization.md)与[轮次导航验收](verification-2026-10-22-turn-navigation.md)。本轮没有改变视觉结构、输入或原生执行语义。

## 验证

- `node --test test/thread-sync.test.mjs`：14 项通过。新增覆盖缓存挂起时仍发起 HTTP、在途读取合并、缓存先返回、网络先返回、切换选择及连接版本、失败后迟到缓存。
- `npm test`：389 项 Node、68 项 Python 全通过。`git diff --check` 通过。
- ego-browser 使用固定 4327 端口及独立状态目录。浏览器 API 全部由 fixture 拦截，没有操作真实业务会话。
- 同一模拟数据，每次 IndexedDB 读取人为延迟 300ms 并返回未命中。桌面旧版一次切换为 740.7ms、缓存读取两次；新版三次为 16.5 / 52.6 / 23.9ms、每次读取一次。计时从调用侧栏点击到检测正文节点出现，不是网络或纯渲染的独立耗时。
- 390px 新版三次为 989.2 / 38.1 / 30.4ms。首个异常慢样本保留，尚未定位原因；不能声称所有帧或所有切换均流畅。无窄屏旧版对照。
- 桌面及 390px 快速往返切换、迟到 HTTP/缓存、草稿保留通过；无页面横向溢出、脚本错误或 API 写入。Escape 收起侧栏并返回有可见轮廓的焦点。截图已查看。

## 范围与代价

这组性能结果只证明消除了慢缓存串行阻塞，不代表真实会话的总体加速比例。没有测量真实长会话、SSH 历史解析或系统资源峰值。缓存命中时，并行网络可能已启动 preview，比原先等缓存后直接读完整详情多一次 preview；未新增轮询，未缓存另一份业务状态。原文渲染与日志解码仍走原有路径。

没有修改输入处理，未重新验证系统中文输入法、实体手机或软键盘。浏览器自动化首次重载保留模拟连接参数，收到 UNKNOWN_HOST；随后从无参数入口重新注入 fixture 后完成验证，该失败不计入性能样本。
