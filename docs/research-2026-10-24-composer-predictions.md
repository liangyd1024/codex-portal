# 输入预测调研与实施阻塞（2026-10-24）

## 结论

用户授权开始接入 Composer predictions 后，首先通过现有传输连接执行原生接口验证。当前引擎虽然导出了预测请求协议，实际调用返回 `-32601`：

```text
thread/prediction/request is not implemented yet
```

因此，当前版本不能把该请求标为可用。RCM 尚未实现或上线输入预测。本次只增加调研记录，不修改运行时代码，不部署网页，不修改或重启 Codex。

版本范围：RCM 开始核验时的 `master` 基线为 `0d9f337`；桌面应用 `26.1016.62342`（构建 `21477`）；配置所指原生引擎 `0.163.0-alpha.11.2`。这是本次实测范围，不代表其他版本也未实现。

1. 从仓库外的连接配置读取本机目标。复用 `localTunnel` 和 `RpcClient`，连接已有输出转发服务。未启动或重启目标引擎。

4. 原生测试轮次正常完成。只使用该测试会话及其已完成轮次请求预测。
5. 预测请求被明确拒绝，错误码及正文如上。没有把接口拒绝解释为无建议、账号不符合资格或网络超时。
6. 核对测试会话空闲后，通过原生接口退订；随后再次核对已完成轮次并归档测试会话。未操作原业务会话。

测试会话身份、临时目录和原始记录保存在仓库外。未发起第二次预测尝试，未尝试切换凭据或开启隐藏权限。

## 协议存在不等于实现可用

分别导出默认协议和 `--experimental` 协议，未连接业务服务：

| 项目 | 默认协议 | 实验性协议 |
| --- | --- | --- |
| `thread/prediction/request` | 不包含 | 包含 |
| `thread/prediction/updated` | 包含 | 包含 |
| `thread/fork.experimentalPredictionMode` | 不包含 | 包含 |

预测请求参数为 `threadId`、`sourceTurnId`。请求响应结构为空对象。结果通知关联相同的两个 ID，结果可为 `completed` 或 `failed`；完成文本可为空。

未来适配必须同时核验协议和运行时行为。当前版本仅检查 schema 就把 `prediction.supported` 设为 true 会误报。真实可用性至少需要请求成功、结果通知可关联，并核验新轮次、连接变化和无建议的行为。

## 何时不生成、隐藏或取消

以下来自当前桌面包静态分析，未逐项进行真实推理验证。

### 跳过生成

- 本地偏好关闭、功能开关未开放、远程配置不可用或关闭、采样未命中。
- Plan 模式、非 OpenAI 提供方、服务端禁用模型、引擎不支持预测分叉。
- 同一机器、会话、来源轮次已有成功缓存。空结果也是有效缓存；`live` 与 `catch_up` 共用缓存键，不因等待而反复生成。
- 轮次结束触发路径排除非 owner、临时会话、侧边聊天及 aeon 类型；来源轮次必须仍为最新轮次。
- 进入会话补取路径要求会话 ready、连接 connected、存在已结束轮次、运行状态非 active，且该来源轮次未被清理。

`retry: false` 表示当前请求不自动重试。请求异常与成功返回空值不同，后续独立触发仍可能重试异常请求。

### 仅隐藏建议

前端使用编辑器装饰层；建议未接受前不属于草稿。只有单一空段落、无输入法组合态、无补全菜单时才显示。草稿、附件及附件处理、图片标注、听写或转录、语音布局、待处理审批或输入请求、输入器禁用均可隐藏建议。这些展示条件不直接阻断后台预测。

窗口失焦不等于取消。切换会话或卸载输入组件可以终止前端等待，但当前调用没有把消费者取消信号传入后台生成。

### 取消与失败

- 预测进行期间，源会话开始新轮次，会清理查询并请求取消临时预测。监听在预测结束后移除；已完成旧缓存由后续不同来源轮次的请求清理，不能泛称每次新轮开始都立即清掉所有已完成缓存。
- 预测设置变化、账号身份变化、注销和控制器销毁会触发相应清理。
- 等待结构化预测结果默认超时 30 秒；此前获取配置、恢复和分叉会话不包含在该计时内。
- 取消会尽力调用临时预测轮次的 `interruptTurn`，最终退订临时会话。网络异常时不能保证底层立即停止。
- 模型返回合法 `suggestion: null` 属于成功弃答。无文本、非法 JSON、结构不符、轮次失败或超时属于失败；安全策略还可能在生成后抑制结果。

没有发现独立的活动 Goal 禁止条件。轮次结束预测路径未要求状态必须为成功；用户停止或轮次失败后不能保证绝不预测。模型选择何时主动弃答的详细语义来自远程提示词，本次未取得其正文。

## 解除阻塞后的接入方案

优先验证实现后的原生预测请求及通知。沿用 HTTP/JSON、SSE、原生身份和控制权，不新建预测引擎或轮询任务。

- 服务端独立适配模块处理资格校验、同轮请求合并和原始结果缓存；明确要求能力受支持。通知可能先于请求响应。
- 按连接代次、账号、会话和来源轮次隔离结果。切换连接、账号、会话或开始新轮次后，迟到结果不得覆盖草稿。
- 前端保留原生 textarea 及现有行内引用层。灰字不写入草稿；接受后只插入文字，不发送。复用现有样式变量。
- Tab、右方向键、Enter 的接受处理必须早于发送处理，避免一次按键接受并误发送。保留中文输入法组合态保护。手机接受控件必须支持触控且满足尺寸规范。
- 对预测通知单独分流，避免落入通用更新逻辑而重新读取整段历史。渲染和打字不能触发重复请求。
- 不得用原会话 `turn/interrupt` 模拟取消预测。当前协议没有预测专用取消接口，也不返回预测分叉 ID。

待验证范围包括原生资格与取消语义、桌面和手机模拟、真实中文输入法及软键盘、SSH 目标。当前均未标为预测功能通过。
