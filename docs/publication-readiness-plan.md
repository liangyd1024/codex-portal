## 目标和协作边界

继续使用现有 GitHub 仓库。优先支持 macOS。新用户克隆后，通过明确的安装入口检查依赖、初始化自己的连接并启动网页，不需要手改 JSON。已有用户保留连接 ID、机器 ID、配置、草稿、证书和配对数据。

Git 保存源码、依赖清单和锁文件。依赖及所需工具在使用者机器上按版本下载。安装包、node_modules、构建目录、运行数据、真实配置和密钥不进入 Git。以后如分发安装附件，也应作为单独发布资产，不能混入源码历史。

迁移会话独占框架分支的修改、验收与合并。此计划不修改迁移工作树，不重复合并。所有依赖新框架的运行时代码修改，等待迁移会话完成验收并整合到 master。当前仅在 master 完成只读审计、计划和交付规格。提交和推送串行进行。

不停止原生会话、任务或引擎。不改写 Codex 原生数据和全局配置。RCM 配置、缓存和展示状态独立保存。

## 阶段 1：正式产物和安装入口

前置：框架验收及 master 整合完成。

1. 移除 package.json 中会部署服务的 install 生命周期。常规依赖安装不改 launchd、不重启服务、不创建真实连接。
2. 将环境检查、初始化、构建和正式安装拆成明确命令。命令名在实现时落入 package.json 和 README，本文件不提供尚不可运行的安装命令。
3. 构建可脱离开发目录运行的产物：前端静态资源、编译后的服务端、必要原生适配脚本、运行时依赖及锁文件。明确哪些依赖已打包，哪些必须随产物安装。不得依赖开发 node_modules 或开发目录的 latest.json。
4. 清单记录源码提交、工具版本、依赖锁摘要及完整运行文件摘要。排除机器绝对路径和个人信息。部署前校验清单并验证同一产物，不能测试 A 后重建并部署未验证的 B。
5. 使用独立暂存目录准备完整 release，再切换正式服务。端口保持现有约定；端口占用先诊断，不能自动改号。保留上一版本及本地回退入口。
6. 更新沿用版本校验。未来清理历史后的首次升级使用一次性迁移流程，不能普遍关闭祖先检查。不得将常规更新和历史迁移混成同一条宽松路径。

验收：全新目录安装可启动；移走开发目录后仍可运行；失败时可恢复上一网页版本；原生任务持续运行；构建和安装清单无个人路径。

## 阶段 2：macOS 首次初始化与环境检查

1. 检测受支持的 Node、Python、Codex 路径与原生接口能力。发现结果写入 RCM 自有配置。只读探测不得启动或停止目标引擎，不以修改 Codex 安装文件补齐接口。
2. 有 Homebrew 时按已确定的依赖策略安装缺失工具；没有 Homebrew 时给出明确指引。检查 age 备份工具及现有发布验证所需浏览器工具，区分运行必需、备份可选和开发验证依赖，不能要求新用户具备维护者环境。
3. 初始化创建本机连接和稳定身份。重复运行只补缺省字段，不覆盖现有连接、默认目标、证书、配对或用户配置。
4. 统一配置路径、状态路径、Python、Codex 二进制及数据目录的解析。SSH 使用目标环境发现结果，不套用本机路径。
5. 对配置损坏、依赖缺失、原生接口不可用、权限不足、端口冲突给出可执行恢复说明。安装前后的检查不自动进行数据备份。

验收：新用户无需手改 JSON；已有用户重复初始化不丢数据；自定义目录有效；缺失依赖和不可用原生接口不被标为成功。

## 阶段 3：连接管理与稳定身份

在 React 页面和服务端连接服务实现新增、检测、修改、默认设置及移除。连接测试只验证实际开放且已核实的能力。保留严格 SSH 主机校验、身份验证及 Origin／CSRF 防护。

配置保存使用版本比较、串行写入和原子替换。旧页面提交过期配置须明确冲突，不能覆盖新配置。连接改名不改变连接 ID 或机器 ID。把旧 ID 指向另一台机器须防止历史、缓存和草稿串用。

修改连接后协调 Manager 生命周期、路由缓存、SSE 订阅和前端连接集合。迟到响应不得覆盖新连接页面。移除入口只解除 RCM 连接，不停止目标服务。草稿、当前会话与任务展示按稳定身份恢复。

验收：两个标签页并发修改、保存失败、切换中断、旧请求迟到、同名不同目标、改名和移除均覆盖；原生业务操作仍由原生接口执行。

## 阶段 4：现有数据保护、手动备份与回退

统一 scripts/data-backup.py 的配置及状态路径，核对 .archive-sync.json 等实际状态遗漏。区分源码版本和已安装版本。按现有许可范围保留手动本地加密备份，不包含 Codex 登录凭据、原生会话数据或 SSH 私钥。

移除运行数据向 GitHub 发布和下载的流程及其 gh 运行时依赖。历史已上传附件另行审计，移除代码不代表远端附件已清除。

浏览器备份支持按连接选择导入，先校验身份与格式并预览冲突，不因连接集合不同而只能整份拒绝或整份覆盖。保留原有本机与 SSH 连接及绑定数据。恢复按现有维护检查与明确授权执行；网页升级不自动触发恢复。

验收：现有配置升级、重复迁移、部分备份导入、损坏备份、回退和自定义目录；不借停止原生任务实现网页更新。

## 阶段 5：公开仓库与交付

先完成源码、文档、测试样本、截图、构建产物及 Git 历史审计。示例使用虚构信息。无命中的自动扫描只能作为辅助证据。

继续使用当前仓库。先形成可审核的历史处理清单及仓库外私有归档，再安排串行历史切换。不得提前强推、重建远程仓库或删除分支、标签和附件。涉及批量删除时交由用户手动处理，不拆分绕过。

最终统一默认分支为 master，并核查旧分支、标签、Releases、PR 及 Actions 是否仍暴露旧内容。清理历史前后保留现有部署更新和本地回退能力。按需配置发布验证流水线；流水线不能部署维护者本机或接触真实凭据。

README 分开描述新用户安装、已有用户升级、SSH 接入、故障诊断和回退。记录 Mac 架构实际验证范围，不把单一架构结果外推到全部 Mac。
