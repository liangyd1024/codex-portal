# 临时侧聊生命周期对齐

代码基线：`fd80f9b`。实现提交以本文件首次提交所在版本为准。

## 核实结论

只读检查本机桌面 `0.163.0-alpha.11.1` 应用资源，未修改安装文件。

- 主进程 `.vite/build/src-CsH31EEu.js` 的 inactive unsubscriber 中，`ux` 判断临时侧聊；数量候选排除临时侧聊，但 `ttlExpired` 仍包含它们。TTL 为 `108e5` 毫秒，即 3 小时。
- 活动视图、跟随者和运行状态保护沿用该模块的判断；空白会话保守保留。退订后临时侧聊被标为 `needs_resume` 和 `notLoaded`。
- 渲染资源 `local-conversation-thread-346380d3959a.js` 明确提供侧聊过期说明及“Start new side chat”动作。它不是普通持久会话的无损恢复。

独立原生引擎实测：创建专用持久测试会话，完成一轮简单文本，再原生 fork 为 ephemeral 侧聊。退订返回 unsubscribed，按该测试引擎 5 秒卸载延迟等待 7 秒后，加载列表不再包含侧聊；同 ID 的 thread/resume 返回 -32600，提示 no rollout found。之后归档本次持久测试会话，仅关闭本次独立引擎。没有操作既有业务会话。

桌面策略依据来自安装代码和已有界面验证记录，本轮没有点击真实桌面侧聊完成 3 小时等待。不能把源码核实写成桌面交互实测。

## 修改

临时侧聊接入现有 TTL 回收，不占普通会话的 10 个名额。完成过轮次、空闲且没有活动页面时才参与回收。保持原有运行任务、后台命令、队列、待处理问题和操作竞态保护。

页面存在上报同时携带主会话和可见侧聊。关闭面板、切换主会话及关闭页面会更新保护范围。重复相同状态仍复用请求，不增加轮询。原生检查期间重新打开侧聊会取消释放。

过期后停止尝试恢复原临时 ID，保留当前页面中的旧聊天展示，提供“开始新侧聊”。新侧聊通过原生 fork 创建，保留未发送的文字、选文和图片草稿；不重放旧聊天，不自动发送。失败仍可重试同一创建请求，避免重复 fork。

服务端过期后释放侧聊消息缓存和容量名额；保留轻量创建回执，避免迟到重试重复创建。RPC 连接变化仍清理连接内缓存。RCM 不建立原生聊天记录的持久化副本。

## 验证

- `npm test`：652 项 Node、72 项 Python 测试通过。新增 TTL 与普通数量限制分离、空白/可见侧聊保护、过期不恢复、缓存释放、创建去重和草稿转移测试。
- 使用 ego-browser 在隔离页面加载当前前端模块，所有业务 API/SSE 均模拟。开发预览端口被其他任务占用，没有停止其他任务或换端口。此处不是正式业务接口端到端验证。
- 桌面 1440×1000：关闭与重开保持同一侧聊及草稿，不增加创建请求；过期后新建只创建一次，文字和选文草稿保留。键盘 Escape 关闭、焦点返回及重新打开通过。请求记录中消息发送数为 0。
- iPhone 12 参数 390×844、DPR 3、mobile、5 点触控及 coarse pointer 均已核对。触控“开始新侧聊”成功；全选后中文粘贴保留，Enter 换行，没有发送。
- 补测 iPhone 17 参数 402×874、DPR 3，横屏 844×390 和高度缩小 390×480；没有页面横向溢出。目视检查桌面和手机过期页面截图。复用原有按钮样式和焦点规则，未改 CSS。
- 图片草稿转移通过代码回归验证，未做实体手机图片上传测试。实体手机、真实软键盘、系统剪切菜单和中文候选窗未实测。

性能验证范围：关闭并重新打开未过期侧聊，没有新增原生创建或消息请求；回收复用单个截止时间定时器；原生卸载后加载列表不再含测试侧聊。未做数小时压力测试，不声称所有泄漏已排除或性能最优。
