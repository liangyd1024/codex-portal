## 已实现范围

- 锁定 React、TypeScript、Zustand、Vite 和 Fastify 的直接版本及依赖锁文件。
- 独立类型检查。构建前检查实际依赖与锁文件。新增 TypeScript 使用严格检查；保留的 JavaScript 不在严格类型检查范围内。
- 每次构建写入全新目录。Vite 不自动清空目录。产物记录源码提交、未提交状态和资源摘要。
- TypeScript 服务端分离应用组装、HTTP 协议处理和路由分发。连接、会话、桌面／定时任务、文件／图片、侧栏／目录／输入工具、手机访问及系统接口已拆为独立路由和应用服务，SSE 生命周期独立封装，复用现有原生适配模块。
- Fastify 在请求体解析前进入兼容分发器，保留 Host、Origin、手机鉴权、CSRF 和请求体处理顺序。
- React 挂载原页面结构，诊断、模型及连接选项、排队消息与手机访问设置使用 React 渲染。页面顶层状态通过 Zustand 保存；原有草稿和原生数据保持对象身份。
- 保留消息解析、缓存、节点协调、输入流程与手机适配模块。
- 原 CSS 未改变。构建保持样式表内容与加载顺序。
- JavaScript 启动入口转入隔离验收服务。原安装入口保留，本轮不运行安装。
- 验收网页使用 4327；手机代理使用 4338；手机 HTTPS 使用 4339。
- 状态、日志、手机配置、证书、配对及更新状态使用独立目录。
- 手机 Cookie 单独命名。Cookie 不区分端口，单独命名可避免覆盖同一主机上的正式手机登录。
- `/api/system/update` 在真实验收入口拒绝更新正式服务。

## 尚未完成的迁移

当前实现是可运行的迁移检查点，**不是整份计划已完成或完整验收通过**。

- 前端主控制器和多数功能模块仍是 JavaScript。排队消息和手机访问设置已迁至 React/TypeScript 组件；侧栏、输入框其余部分、其他设置和手机抽屉还未完成完整迁移。
- 模型选项和诊断内容已移回同一 React 组件树，取消嵌套独立根，通过 Zustand 订阅更新。其余 React 静态结构与旧控制器之间仍需收敛 DOM 所有权，不能据此认为所有子树已完成迁移。
- 服务端连接、会话、桌面／定时任务、文件／图片、侧栏／目录／输入工具、手机访问及系统接口已拆分路由与应用服务，SSE 生命周期已独立封装；原生请求回复已拆分路由和应用服务，静态资源与未配对登录页也已移入专用路由；总分发器保留请求顺序、安全校验和公共错误处理。
- 验收环境的 `--mobile` 启动入口已接入独立局域网配置回调，复用预览 CA、证书与配对数据。验收环境不修改系统 Tailscale 转发；该方式明确返回限制，不能把局域网功能写成完整手机管理功能通过。

## 开发操作

使用 Node.js 22.12 或更高版本（Vite 8 的运行要求）。在此重构分支的独立工作树内执行：

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run typecheck
npm test
npm run start:preview -- --mobile
```

`npm test` 会先构建，再执行 Node 和 Python 测试。不需要再次构建。
禁止用 `npm install` 或 `npm run install` 初始化开发环境；原安装生命周期会部署正式服务。
启动前检查 4327、4338、4339 的占用原因，不自动换端口，不停止正式进程。

默认创建新的私有临时状态目录。重启同一验收实例时，可将 `RCM_PREVIEW_ROOT` 设为已有验收目录的绝对路径。目录必须带有本程序生成的验收标记；不能复用其他非空目录。

手机需要信任本次验收独立生成的 CA，并使用验收页面生成的配对码。证书和配对数据不能复制到正式手机目录。真实操作只针对专用测试会话，不同时从两个入口控制同一会话。
