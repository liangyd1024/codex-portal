# Mac 通知展示与确认修复

真实证据：17:46:10 其他会话完成事件已到网页，用户截图显示浏览器 onshow，但 Mac 通知中心无 RCM 通知。通过系统设置只读检查确认两个 Google Chrome 条目的允许通知均关闭，而 DeepSeek Harness 开启。用户授权开启后，重新读取系统设置发现两个 Chrome 条目均已由用户调整为开启（桌面、声音、标记），没有反复切换用户已设好的开关。真实弹窗恢复仍等待用户测试确认。

独立代码缺陷：后端以展示 alias 生成通知键、前端以稳定连接 ID 确认，导致待确认记录不能正确移除；前端在调用 Notification 前即去重标记，构造失败、onerror 及超时也会被当作已处理。上述缺陷不是这次 macOS 关闭应用通知的替代解释。

修复：后端使用稳定连接 ID，兼容旧 alias 队列；重放确认携带服务器原始键。前端持有跨页 Web Lock 直到 onshow 或失败/10秒超时，只有显示反馈后写去重并确认；失败可在后续重放时重试。切换连接期间不把迟到通知确认发到新连接。提示明确浏览器报告显示仍可能被系统通知开关拦截。未自建系统通知守护进程或修改原生 Codex 数据。

验证：npm test 218 Node / 53 Python 通过，日志 /tmp/rcm-notification-delivery-final-tests.log；新增稳定 ID/旧 alias 兼容、无效确认、构造异常、异步错误、超时、成功后去重测试。ego-browser 空间117、独立4327预览与 fixture：首次失败无确认，重放成功后按原始服务器键确认；无脚本错误。桌面及390px无横向溢出、测试按钮键盘可触发且焦点可见。截图 /tmp/rcm-delivery-desktop.png、/tmp/rcm-delivery-mobile.png。通知 API 为模拟验证；用户提供了真实系统设置前的结果。未修改输入流程，未复测中文输入法。预览进程70108已通过原执行工具Ctrl+C退出，浏览器验收空间已关闭。
