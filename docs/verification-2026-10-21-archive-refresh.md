# 归档与刷新体验验证

## 改动

- 归档点击后立即在当前账号的普通列表隐藏。后台沿用原生归档接口和串行队列。旧列表响应不会让待归档项重新出现。
- 原生归档失败立即撤销隐藏并显示原始错误。已确认归档但列表刷新失败时继续隐藏。桌面同步失败沿用服务端部分成功提示，不重发归档。
- 成功后沿用撤销入口。切换账号后不向新账号显示旧操作结果。
- 左侧数据和显示状态不变时保留 DOM、焦点和滚动位置。活动采样时间不参与显示比较，实际活动状态仍参与。
- 后台刷新不再反复切换工作区标题及无分页列表底部的加载按钮。输入内容、宽度和字体未变时不重复将输入框高度降为 0。

## 证据

- 修改前 ego-browser 真实页面侧栏按钮在周期刷新后失效。模拟页面主动刷新后，原会话按钮 isConnected=false；输入框出现 height:0px 的中间写入。
- 修改后模拟页面主动刷新，原会话按钮 isConnected=true，输入框高度无写入，正文 scrollTop 保持 17382。
- 归档延迟请求期间会话立即隐藏；模拟失败后恢复，显示“归档失败验收”，焦点回到对应菜单按钮。
- 390px 窄屏用 End / Enter 操作归档成功，有撤销入口，无页面横向溢出。截图 /tmp/rcm-archive-mobile.png。
- 阅读位置 scrollTop=1200 在刷新后保持不变。中文草稿保留，合成输入法候选 Enter 事件未发送。没有执行真实系统输入法候选操作。
- 浏览器验证使用现有 4327 预览及 test/fixtures/mobile-browser.js 拦截 API。该预览同时包含其他会话正在开发的问答提示内容。本轮没有启动或停止该预览，也没有归档真实业务会话。
- npm test：316 项 Node、58 项 Python 通过。日志 /tmp/rcm-archive-tests.log。最终小改动后补跑结果见下文。

## 交付边界

本次仅提交归档、刷新相关改动。其他会话的未提交文件保留。正式部署状态及提交追溯后续补录；不能将模拟预览记为真实原生归档验收或正式上线。
