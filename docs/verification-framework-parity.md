## 方法与证据边界

1. 真实服务单独验证 Host、Origin、手机配对、连接及专用测试会话。
2. 双版本静态测试入口分别加载 master 原页面与重构构建产物。使用同一份浏览器模拟数据，方便复现输入、流式消息和异常状态。
3. 静态测试入口不创建 Manager、SSH 或原生引擎连接。未被模拟截获的 API 请求返回失败，不会转发到真实服务。
4. 静态入口使用测试用临时端口及独立浏览器 Origin，避免修改 4317 / 4327 的浏览器存储。它们不替换 4327 / 4338 / 4339 验收服务。
5. 真实数据与截图在仓库外保存。报告只记录虚构样本和汇总结论。
6. 浏览器模拟与实体手机分别记录，不把模拟软键盘高度当作实体软键盘验证。

## 新建失败场景的行为边界

模拟创建接口返回明确错误响应（HTTP 503）后，两版均允许再次提交，草稿不变。第二次创建请求等待期间连续点击两次，总创建请求仍只有两次（一次失败、一次进行中）。随后创建成功，首条消息接口返回 503，两版均显示“发送结果待确认，请勿重复发送。草稿已保留。”。

## 焦点差异归因与目录组件复验

### 调试扩展的因果证据

最小页面只包含按钮、禁用状态和 `Response.text()`，不加载 RCM 业务。原生属性赋值和属性设置均保留快速响应后的焦点，React 本地状态与 Zustand 更新均失焦。进一步分离事件和更新后，React 事件加原生 DOM 更新保留焦点，原生事件加 React 更新仍失焦；原生按钮禁用后主动读取矩形也会失焦。慢请求时各实现均失焦。

对矩形读取进行调用栈追踪，实际触发者是浏览器 React DevTools 扩展的 `measureHostInstance → getClientRects → updateFiberRecursively → handleCommitFiberRoot`，发生于 React 提交回调。随后执行启用—停用—恢复的 27 次按钮对照：只在该隔离页临时停用扩展提交回调时，React 本地状态及 Zustand 的快速请求焦点均恢复；恢复回调后差异再次出现。原生对照始终保留焦点。该证据纠正了先前把快速失焦直接归为应用迁移回归的判断。

没有修改 React、扩展安装文件、全局浏览器设置或应用来绕过调试器。后续隔离对照在页面准备完成后暂存该页的 `onCommitFiberRoot`，仅在测试期间停止此测量回调，每组结束恢复；导航也会重新建立正常扩展环境。测试条件显式记为“排除 React DevTools 提交测量”，不能写成扩展开启时行为也一致，更不能声称覆盖了全部浏览器扩展组合。早先受此扩展影响的浏览器耗时样本也不能直接用于无调试测量的性能结论；服务端独立进程样本不受本项发现影响。
