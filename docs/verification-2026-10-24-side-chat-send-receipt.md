# 侧聊重复发送占位修复

基线：`29df655`。实现提交以本文件首次提交所在版本为准。本次只修改侧聊发送文本归一化及回归测试。轮次导航修改由其他任务提交，本次没有改动其文件。

## 根因与修改

选文包装函数 annotatedText 会在首尾加入换行。侧聊先用未去除首尾空白的文本建立发送占位，服务端 messageInput 则在提交原生 turn/start 或 turn/steer 前调用 trim。原生 userMessage 返回后，按文本精确匹配的回执无法消除占位，因此出现原生输入和回复已经展示、底部仍有“已发送，正在同步会话”的重复气泡。

侧聊现在先按服务端相同规则去掉首尾空白，再共用该文本建立占位和发送 HTTP 请求。内部换行、选文、实际问题和原生消息保持不变。不以“出现助手回复”猜测某条输入已被接受，不增加轮询或重发。

## 验证

新增测试调用真实 messageInput 构造原生输入，修改前稳定复现占位残留；修改后通过。覆盖新轮次与运行中引导、SSE 早于和晚于 HTTP 确认四种组合，并核对内部换行、单次请求、单条原生用户消息及迟到回执不复活占位。

完整 npm test：659 项 Node 测试及 72 项 Python 测试通过。已有失败草稿、重复发送、图片回执和跨会话迟到响应回归保留。
