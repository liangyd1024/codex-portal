# iPhone 设备模式审计

## 环境与范围

使用 ego-browser，在隔离开发预览加载实际前端。通过 `test/fixtures/mobile-browser.js` 拦截 API 和事件流。设置移动视口、DPR 3、触控模拟，并核对 `maxTouchPoints=5` 和粗指针。按钮使用 CDP 触控事件操作。模拟配置、配对、撤销和更新请求没有到达真实服务。

设备参数：iPhone 17 使用 402×874；iPhone 14 与 iPhone 12 共用 390×844 的尺寸检查。另检查对应横屏和 390×500 可用高度。iPhone 17 的物理分辨率依据 [Apple 技术规格](https://www.apple.com/iphone-17/specs/)，模拟按 DPR 3 换算。浏览器内核仍为 Chromium，不能据此声称完成 iOS Safari 或实体机兼容认证。

## 发现和修复

| 问题 | 复现与结果 | 修复 |
| --- | --- | --- |
| 横屏侧边聊天无法发送 | 844×390 展开引用后，发送按钮位于 y=375–419，底部被裁切 | 输入表单允许内部滚动，标题保留；移动面板跟随可视区域高度 |
| 横屏注释评论无法编辑 | 展开注释后，评论输入框宽度仅约 12px，注释按钮也被压窄 | 注释区独占一行，输入框恢复全宽；注释与输入区域限高滚动，发送按钮可滚动到达 |
| 全选剪切遗留图片 | `Meta+A`、`Meta+X` 产生大写按键事件时，全选状态被提前清除 | 统一按键大小写；增加大小写复制、剪切及整体删除的行为测试 |
| 通知记录过多 | 用户要求只保留最近三条 | 上限由八条改为三条，保留最新优先顺序 |

## 验证边界

本轮不是所有后台能力的实体手机端到端认证。原生创建、临时分叉及上下文继承的真实服务证据见[选区工具验收](verification-2026-10-22-selection-tools.md)。完整自动化套件覆盖连接、原生适配、鉴权、备份恢复、异常结果和重试逻辑；不能将这些测试写成手机实测。

实体 iPhone 的选区手柄、剪贴板菜单、软键盘、中文候选窗、Safari 特有行为、锁屏恢复、相册 HEIC、证书安装、推送权限及系统文件管理仍未实测。语音入口已按之前需求移除，本轮没有重新添加。
