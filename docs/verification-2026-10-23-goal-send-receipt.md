# 目标发送占位清理

## 原因与修改

原生依据见 `verification-2026-10-20-inline-goal.md`。纯文字目标通过目标接口启动执行，不额外发送普通消息。原发送回执只等待新的原生 `userMessage`，因此目标已执行时仍显示“已发送，正在同步会话”。

目标准备成功后，纯文字提交返回页面内的 `goalOnly` 标志。发送回执据此确认并在下一次渲染时清除。此标志只表示已完成的提交路径，不写入原生历史、配置或数据库。普通消息和目标附件仍按原生消息身份确认。目标失败及未知结果保留既有草稿保护。

## 验证

- 相关测试 13 项通过，覆盖目标无普通消息时清理、图片仍等待原生消息、同文重复发送、先事件后响应、跨连接隔离及失败。
- 完整 `npm test`：426 项 Node、69 项 Python 测试通过。
- ego-browser 独立预览，所有 API 请求使用模拟数据，未向真实引擎发送目标。
- 桌面 1440×900：中文目标用 Enter 发送；挂起目标接口时保留占位与草稿；响应后占位移除且草稿清空。仅调用一次目标写接口，无额外普通消息写请求，无横向溢出及脚本异常。
- iPhone 12/14 共用尺寸 390×844、DPR 3，移动视口和触控模拟启用；执行前确认宽度 390、DPR 3、触点数 5。触控选择目标并发送；挂起与成功状态符合预期，无重复占位、横向溢出或脚本异常。
- 单次桌面模拟测得接口释放到占位 DOM 清除约 3.3 ms。不增加请求、轮询或定时器；不代表真实网络延迟或性能最优。
- 本次没有修改输入事件或样式。未重新验证实体手机、中文候选窗、系统剪贴板、全选剪切粘贴、横屏及真实软键盘。未进行真实目标执行链路验证。
