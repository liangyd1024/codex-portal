# 侧边聊天首条输入保留

## 修改与依据

依据用户截图及已有侧边聊天核验记录。本轮发现侧边聊天缓存会用非空轮次 items 整批替换已收到的消息；部分轮次快照可使先到的用户输入消失。改为按原生消息 ID 合并，保持原文。迟到的开始响应补齐缺失消息，但不覆盖已流式更新的消息或回退终态。服务端和浏览器共用该缓存逻辑。不写入原生数据，不生成替代消息，不新增网络请求。

尚未取得用户截图对应的原生事件序列，因此没有断言该历史实例的确切触发顺序。未重新核验 Codex 桌面界面。

## 验证

- 相关测试 10 项通过。覆盖首条带选文输入、部分完成快照、迟到开始响应、终态保留、重复消息去重、原生数组不被缓存修改及服务端重新读取。
- 完整 `npm test`：472 项 Node.js、69 项 Python 测试通过。`git diff --check` 通过。
- ego-browser 独立 4327 预览，全新状态目录。组件级模拟 API，加载实际侧边聊天模块及公共样式，消息渲染适配器使用公共文本解析和 Markdown；未调用真实引擎发送接口。
- 桌面模拟键盘 Enter 发送；完成事件先于发送响应到达，用户输入仍存在且只有一个气泡。白字黑底，无横向溢出。
- iPhone 12：390×844、DPR 3、mobile、触控及 coarse pointer 已核对。首条输入可见；触控关闭后重新打开仍保留。844×390 横屏及 390×500 缩小高度无页面横向溢出。截图已查看。
- 模拟 100 次增量到两个动画帧约 14 ms，原用户消息 DOM 复用，没有新增网络请求。这是本机组件样本，不代表真实网络或长会话性能最优。

本轮没有改动输入逻辑或 CSS。实体手机、真实中文输入法及软键盘未实测。真实临时会话端到端流程未验证。浏览器任务空间已结束。
