## 编辑流程

四视口 120 个样本、60 组配对一致。覆盖打开、取消后草稿恢复、空白校验、合成组合键盘事件、保存等待、冲突与重试、结果未知时先读取确认、重新读取、断线提示，以及编辑框和技能目录之间切换。比较完整文案、输入值、禁用／只读／隐藏属性、计算样式、几何位置、焦点、浏览器草稿、目标对象与写请求。

明确冲突后的重试请求与前次相同。结果未知后再提交先读取核对，确认目标已经保存时不重复写入。主输入草稿始终保留，技能目录内没有残留目标 form，重新进入编辑框后只有一个目标 form。无页面异常或横向溢出。

初轮脚本把其中一个阶段命名为 unchanged，但后续视口仍保留前一轮编辑草稿的 base，实际提交改变了目标。两版该行为一致，却不能据此证明“无变化零写入”。原样本保留，零写入要求另行按当前目标原文验证，不以阶段名称作为证据。

## 快速及延迟失败

另补四视口 32 个样本、16 组配对一致。覆盖快速 409 拒绝、重新读取、延迟保存和用户主动移焦后收到失败。快速失败与重新读取后的焦点、草稿及反馈一致；用户在等待期间把焦点移到编辑文本框后，两版失败反馈均不抢走该焦点。

此处没有复现排队编辑曾出现的焦点差异，因此没有根据组件实现相似而修改目标编辑代码。

## 工具栏差异与修复

在同一正常调试环境下，工具栏首轮 136 个样本、68 组配对中，有四组快速清除失败的焦点差异：master 保持删除按钮焦点，候选落到 body。三个手机视口还表现为该按钮焦点轮廓不同。其他状态与请求一致；原始失败样本保留，不记为通过。

修复仅涉及 GoalToolbar。React 继续创建节点及状态图标，只有 action 改变时更新图标；组件内 Zustand 订阅独占变化中的禁用、隐藏、反馈、文字和 aria 属性。避免纯忙状态变化提交整棵工具栏而改变瞬时禁用的焦点语义。没有新增 focus()、改变 CSS 或请求协议；既有操作成功后的焦点行为保留。
