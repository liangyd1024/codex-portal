# 容量失败重试的状态判定

## 问题与改动

原实现仅接受原生会话状态 idle。Codex 的失败会话也可能保留 systemError，导致最新轮次已经因 serverOverloaded 失败，却被拒绝并提示“会话尚未空闲，重试已取消”。原生状态依据见既有容量重试与登录恢复验证记录。

现在允许 idle 或 systemError 进入验证流程，并继续核对最新轮次 ID、failed 状态和 serverOverloaded 错误。发送前再次读取原生状态。active、notLoaded、未知状态、待回答请求、连接变化及其他失败均不触发重试。仍调用原生 turn/start，输入为空，保留原有防重放回执。

重试被拒绝后刷新当前会话状态。会话运行或连接不可用时禁用立即重试，并显示对应原因。增加刷新状态入口；刷新不会发送重试，状态恢复后清除过期的忙状态错误。结果未知仍禁止重放。原始错误正文不改写。

## 验证

- 相关测试 13 项通过。新增覆盖 systemError 容量失败、非容量失败和轮次变化、未知状态、提交前转为 active、忙状态后手动恢复。
- 独立暂存快照 npm test：372 项 Node、64 项 Python 全部通过。共享工作区其他会话的改动未纳入本次提交。
- ego-browser 模拟接口、真实页面：重试收到忙状态后主动刷新、禁用按钮、刷新恢复、清除旧错误、刷新不产生 POST、后续手动重试仅一次、成功后收起提示通过。无脚本错误。
- 1280px 桌面与 390px 窄屏检查通过；窄屏无页面横向溢出，两项可见按钮高度均为 44px。
- 程序化 focus 未激活 focus-visible，不能记为键盘焦点验收通过；已核对按钮沿用公共 focus-visible 样式，实际 Tab 导航未完成。本次未修改文字输入流程，未测试实体输入法。
- 真实服务仅做只读状态检查，未对既有会话触发重试或停止任务。检查时未出现可复现的容量失败，不将模拟测试记为真实过载闭环通过。
