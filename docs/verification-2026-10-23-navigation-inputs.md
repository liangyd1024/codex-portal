# 导航只收录主动输入

## 原因与修改

旧实现对所有原生执行轮次创建刻度，并将没有输入的轮次命名为“继续执行”。原生自动续跑因而出现在提问导航中，原生执行总数也被误用作导航总数。

导航改为只收录含 userMessage 或 goalMessage 的轮次。目标输入识别复用已有原生记录适配。用户主动输入“继续执行”、图片输入和目标输入仍保留。自动续跑正文不变，阅读时高亮前一条输入；阅读位置恢复仍使用原始执行轮次 ID。

历史未加载完时显示“已加载 N 轮”，全部加载后显示“共 N 轮”。当前页全为自动续跑时，仍保留加载更早历史的入口。不新增请求或轮询。

交互依据为既有轮次导航验收记录及本次用户截图。读取用户引用会话的最新原始消息，观察到多个只有助手和工具消息的执行轮次；未遍历完整历史，不报告该会话主动输入总数。

## 验证

- 定向 9 项测试通过。覆盖过滤、原文不变、主动输入“继续执行”、目标及图片输入、续跑阅读映射、分页计数，以及原有分页失败、取消和上下文切换。
- 完整 npm test：476 项 Node、69 项 Python 测试通过。
- ego-browser 使用隔离组件夹具，加载本次源码和现有样式；API 请求全部模拟。开发端口被其他预览使用，没有停止该服务或更换端口。本次不是完整应用预览验收。
- 99 个执行轮次、3 个主动输入显示 3 个刻度，正文仍有 99 个轮次。
- 桌面 1280×900：方向键、Enter 跳转及焦点通过；续跑正文高亮前一个输入。无横向溢出。已查看组件截图。
- iPhone 12/14 共用尺寸参数：390×844、DPR 3、mobile=true、5 个触点、coarse pointer。执行前核实参数。触控选择目录项后关闭目录并聚焦目标正文，无横向溢出。未实测实体设备、真实软键盘或输入法；本次未修改输入流程。
- 初始夹具受 CSP 限制未成功加载；改为调试上下文执行源码。初始滚动容器尺寸设置无效导致等待超时，纠正夹具后阅读高亮通过。未修改服务 CSP。
- 合成性能样本：10,000 个执行轮次，其中 100 个主动输入，20 次平均。旧版全部预览 119.02ms，本次输入筛选及预览 0.53ms。此为本机算法样本，不代表完整应用或真实会话耗时。

代码版本以包含本记录的修复提交为准。正式部署结果另记。不声称完整真实会话导航或实体手机已经验收。
