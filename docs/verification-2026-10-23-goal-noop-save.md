# 目标未变化时跳过保存

## 原因与实现

只读原生记录确认：相同目标有两次独立 user.goal 消息，两次状态均为 blocked，之后普通用户消息才启动单个轮次。正式版编辑目标即使内容未变仍调用原生目标写接口，可能生成重复目标消息。本次不改写历史。

前端在目标内容未变、无不确定回执且当前目标与编辑基线一致时，关闭编辑框，不发送请求。沿用既有首尾空白裁剪规则，不忽略内容内部空白。后端在读取原生目标、校验编辑基线与控制权后，对相同内容直接返回原生目标，不调用 thread/goal/set。保留冲突校验、失败草稿与不确定回执核对；没有自动恢复目标。

原生依据见 [目标栏验收](verification-2026-10-23-native-goal-toolbar.md)。沿用原生目标记录，不将展示去重代替调用修复。

## 验证

- 全量 npm test：449 项 Node、69 项 Python 通过。测试涵盖 active、blocked、paused、complete 的无变化编辑；仅原生读取，无写入；过期基线仍拒绝；内部空白改变仍写入。
- ego-browser 使用已存在的 4327 同仓库预览。先核对进程和工作目录，没有启动、重启或停止其他会话的预览。浏览器所有 API 都由夹具拦截，没有操作真实业务会话。
- 桌面原样保存、首尾空白保存均为零 POST；真实内容修改为一次目标 POST。键盘 Enter 保存后焦点回到工具入口。失败时编辑框和草稿保留，无脚本错误。
- iPhone 12/14 共用参数 390×844、DPR 3、5 触点；启用移动视口和触控，先核对参数。触控打开编辑并原样保存，无新增 POST、无横向溢出。
- 本次未修改布局、输入事件；未重新验证全选、剪切粘贴、中文候选窗、真实软键盘或实体设备。不声称这些项目通过。未向真实引擎提交目标编辑。
- 性能：无变化保存不再发出目标 POST 和后续详情刷新。服务端直接收到同文编辑时仍保留一次原生读取用于校验，避免写入与历史消息增长。未做 CPU、内存基准。
