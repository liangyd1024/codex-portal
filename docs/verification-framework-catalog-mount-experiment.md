# 目录首次挂载性能试验：未采用

## 问题与边界

当前实际候选为 `accb11f`，正式基准为 `227dbfe`；本轮再次 fetch 的 origin/master 仍为 `0a3ee2a`。当前首屏脚本开销高于基准，见[资源复测](verification-framework-startup-resources.md)。

检查发现主输入框和侧聊的技能／插件目录均在启动时注册返回空内容的 React 组件。试验仅将 ComposerCatalog 的注册推迟至首次发布非空视图，并在同一次 flushSync 中注册和发布；首次打开前 clear(null) 不再触发注册。没有修改 CSS、文案、API 或目录解析。

试验构建来自 `29adee3` 工作区的该项修改，资源为 `d6dd794aeea8e697e720169a9c1f3c274c057f8fbdac969b60732f70be47ec27`。只在隔离静态入口验证，没有部署到 4327 或正式服务。下列结果针对试验构建，不能计入实际运行版本的全量验收。

## 同场性能结果

原候选与试验构建的启动提交诊断分别在桌面和 iPhone 竖屏执行原／试验／试验／原。回调包装始终调用原回调并在结束后恢复。四个原候选样本均 72 次，四个试验样本均 70 次。减少的两次对应尚未打开的目录注册；提交数不等于无效渲染数。

## 决定

本次方案未采用。仅减少同步提交，未测得首屏收益，不能满足本轮性能修复的依据要求。已精确撤回该文件的试验修改，核对其与提交版本无差异；试验构建、脚本及原始结果保留在仓库外供追溯。

后续应优先检查同一操作内重复发布的状态和可安全合并的提交，而不是继续以减少启动注册次数代替耗时改善。整体性能门槛仍未通过，本轮没有更新真实预览或正式服务。

撤回后重新执行类型检查与构建，干净构建资源恢复为 `0e4887c7d29f468a80e30e3f66cadc134469600cdab6c2ee7e1f476f801c1ec7`，与实际预览一致。最终再次核对 4317／4327 版本未变。最终交付仅为本试验报告与状态索引，不含应用代码修改。
