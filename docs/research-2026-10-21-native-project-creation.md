# 新建目录与原生项目实测

## 结论

网页端可以通过目标机器的原生接口浏览目录、创建目录、登记项目，并在项目中创建会话。本机与 Ally 均取得真实接口回执。无需自建项目数据库，也无需直接写入 Codex 配置。

桌面自动同步尚未通过：两台机器的原生项目列表已包含测试项目，但桌面 `local-projects` 和 `project-order` 中均没有测试项目。只读检查当前桌面代码也显示，桌面项目创建流程在调用引擎接口之外，还会维护桌面项目缓存、排序和活动项目。不能把引擎成功等同于桌面界面已显示。

此前记录将桌面同步未核实作为整个功能的阻塞条件，表述过于笼统。本次实测将两者分开：核心目录与原生项目功能有可用路径；桌面自动同步没有获得验证。本轮只调研与测试，未新增网页入口或部署功能。

## 环境与边界

- 从 RCM 连接配置读取目标、用户、HOME、二进制路径和 SSH 设置。
- 两端版本均为 `codex-cli 0.163.0-alpha.10.2`。
- 复用已有本机/SSH 传输、身份核验与 RPC 客户端，连接正在运行的目标服务。没有启动、停止或重启目标引擎。
- 创建专用空目录、测试项目和空会话。没有向既有业务会话发送消息。没有发送测试模型轮次，也没有执行生成代码任务。
- 原生写入仅调用 `fs/createDirectory`、`project/create`、`thread/start` 和测试会话的 `thread/name/set`。目录创建使用 `recursive:false`。
- Codex 项目数据库与桌面全局状态只读。没有注入桌面脚本，没有复制当前执行器的工具调用身份，也没有直接写入项目缓存。
- 桌面 UI 自动化被工具以安全限制拒绝，未绕过。已向用户请求人工观察测试项目是否出现在桌面；没有得到观察结果前，不标记界面验收通过。

## 接口与实施方案

1. 项目选择器增加“浏览文件夹”。服务端按当前连接路由，使用配置中的 HOME 作为初始目录。
2. 使用 `fs/readDirectory` 展示目录，使用 `fs/getMetadata` 校验选择；支持返回上级与选择现有目录。
3. “新建文件夹”只接受单个文件夹名，拒绝路径分隔符、空名和 `.` / `..`。调用 `fs/createDirectory` 后重新读取目录确认。
4. 使用 `project/create` 登记选择的绝对路径，传入稳定的请求 idempotencyKey。结果不明时用原标识核对，不生成新标识重试。
5. 从原生项目列表重新加载项目。新会话通过 `thread/start` 传入返回的 projectId 与 cwd。
6. 前后端都绑定连接身份。切换连接或关闭弹窗后，迟到结果不能修改新目标的选择与草稿。失败保留名称和目录，不自动发送用户消息。

发布时必须明确桌面差异：RCM 可使用真实原生项目，但当前验证不支持承诺自动加入桌面项目列表。若要求网页与桌面同步显示，仍需找到具有明确身份和操作回执的完整桌面项目服务，或由用户通过桌面原生流程添加目录后再验证同一项目的归属。不能用直接改写桌面状态弥补。

当前 App Tools 服务依赖执行器传入的 thread/turn metadata 和桌面管道；存在桌面工具不等于独立网页服务拥有调用契约。本轮没有将这些环境变量或调用上下文移植到 RCM。
