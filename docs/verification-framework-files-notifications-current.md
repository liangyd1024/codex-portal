## 通知设置

四视口共 72 个状态样本、36 组配对一致。覆盖初态、权限等待、等待期间重复操作、拒绝权限、初始化失败、开启、测试投递成功、连续投递失败和关闭。比较节点文案、禁用、选中、角色、几何、计算样式、节点身份、偏好存储、权限请求数、注册数和完整模拟投递参数。

每个流程仅一次权限请求，等待期间重复操作未新增请求；测试成功一次，随后三次失败的投递尝试均被记录。关闭后偏好为 false。控件节点保持，实际设备参数正确，无页面错误或横向溢出。

Notification、Service Worker 的注册与投递由夹具模拟。手机分支还模拟 iPhone 标识与独立运行状态，用于验证页面能力分支，不代表安装了 PWA、系统已授权或实体通知中心收到通知。历史时间格式仅在该隔离页固定，便于比较；没有修改产品时间逻辑。仅改动虚构入口的通知偏好键，未清理浏览器全局存储。

## 自动任务通知

四视口另做 48 个样本、24 组配对，全部一致。通过模拟原生事件检查重复成功事件、投递失败、同一失败事件重放、历史事件跳过、新事件投递，以及偏好存储改变后和 storage 事件同步后的状态。

各流程投递尝试数依次为 1、2、2、3、3、3。重复事件只投递一次，失败事件再次出现不重复投递，历史重放不产生新通知；关闭存储偏好后，即使控件尚未收到同步事件，也不继续投递。随后控件同步为关闭。完整投递内容、确认请求正文、通知历史正文和状态均一致，未忽略确认次数差异。各视口使用独立虚构事件 ID，避免旧验收去重记录干扰结果。

## 结论和限制

合计 176 个样本、88 组配对一致。本轮没有产品代码修改、构建或服务重启，因此没有重复运行应用测试；当前候选既有类型检查、构建、884 项 Node／74 项 Python 完整回归证据见目标控件报告。原始脚本和结果保存在仓库外。

模拟投递不能替代真实浏览器权限、系统通知、实体 iPhone 或 SSH 链路验证。本轮没有性能测量，不宣称提速。正式服务与 master 未修改，其他交付缺口仍见[当前交付审计](framework-delivery-status.md)。
