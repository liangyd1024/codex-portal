# 网页菜单与手机登录恢复

## 改动

- 侧栏菜单只显示当前网页实际支持的操作；移除不可执行的排序、项目组织等占位项。不支持的分区操作全部隐藏时，同步隐藏分区的更多入口和右键菜单。连接中断、进行中任务等临时禁用状态仍保留。
- 配对页先通过安全 Cookie 检查已有登录，识别成功自动进入；网络恢复、返回页面或点击重新检查时重试。网络失败不视为登录过期，检查的迟到结果不会覆盖手动配对状态。
- 手机访问说明明确：普通重启与升级不清除登录，继续使用同一地址和浏览器；有效期、退出、撤销、清理浏览器数据仍决定何时需要重新配对。

## 原因与边界

服务已有独立于 release 的 `mobile/sessions.json` 持久化，部署脚本没有撤销登录。本轮未改动其有效期、Cookie 安全属性或 Origin / CSRF 防护。配对页过去没有检查已有登录，补上自动识别以处理已配对设备仍进入配对页的情况；没有证据把用户看到的现象认定为服务重启删除了登录。更换域名、IP 或浏览器不能共享原地址的 Cookie。

## 验证

- `npm test`：88 项 Node 和 24 项 Python 通过；语法与 diff 检查通过。
- 独立临时文件和 HTTP 入口重建：原手机 Cookie 仍能读取访问状态、CSRF 随服务重建轮换、旧 CSRF 不能退出登录、新 CSRF 可以正常退出；退出后重建入口仍拒绝旧 Cookie。验证过期时间不会被重启延长、永久登录保留、主动撤销生效、配对码跨重建仍可使用一次。
- 配对页回归：已有登录无需 POST 配对、失效登录展示表单、网络失败后恢复、迟到检查不会覆盖手动配对结果。
- ego-browser 使用实际前端和模拟 API：分区空菜单入口消失；工作区菜单只剩全部折叠；会话菜单仅显示支持的操作；断线时操作仍可见但禁用；键盘 Escape 和焦点返回正常；1280×900 与 390×844 无横向溢出。模拟有效登录自动进入，模拟服务临时失败后恢复进入，均未输入新配对码。
- 4327 已被另一预览占用，本轮使用仅提供测试资源的临时静态服务 64638；测试脚本和截图在 `/tmp/rcm-menu-session-browser.ubk0pu/`。未操作真实会话或真实手机授权。

实体手机 Safari / Android 重启往返尚未实测；浏览器模拟不能替代真机验证。
