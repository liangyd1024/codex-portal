# 轮次加载状态修复

## 原因与修改

只读核查发现：最新执行轮次不含用户输入。完整历史有 119 个原生执行轮次，其中 19 个含用户提问或目标。按用户输入统计符合现有语义，但历史未补齐时显示“已加载 0 轮”，容易被理解为会话没有轮次。

导航、手机入口和目录标题现在区分待加载、正在加载、失败与取消后的重试状态。完整加载后显示准确轮数。未找到提问时，目录进度显示“正在查找更早的提问”。保留原生消息、计数规则和分页策略。

## 验证

- 完整 npm test：658 项 Node 测试、72 项 Python 测试通过。回归覆盖只有续跑的部分历史、已有提问、失败、取消、重试和完整空历史。
- ego-browser 隔离组件使用当前源码与样式、内存历史样例。桌面验证加载、失败、键盘 Enter 重试；完成后显示 1 轮及 1 个刻度，仅有预期的两次分页调用。
- iPhone 12 模拟：390×844、DPR 3、移动视口与五点触控。执行前核对 innerWidth、devicePixelRatio、maxTouchPoints；触控打开目录及重试，按钮高度 44px，无横向溢出。截图已查看。
- 开发端口被另一项目占用，未停止该服务或改端口。没有完整开发预览；上述浏览器验证是隔离组件验证。未验证实体手机、横屏、软键盘；本次未修改输入流程。

## 性能与限制

本机只读历史读取共 24 页，响应文本累计约 6172 万字符，耗时约 8 秒。字符数不代表压缩后的网络流量，也不代表浏览器渲染耗时。

进度提示复用 rows.length，去掉一次重复索引扫描。没有新增请求、轮询、DOM 节点或预加载。未降低历史传输量，不声称已解决长历史首开性能。

修复版本以包含本记录的提交为准。正式部署结果另记。
