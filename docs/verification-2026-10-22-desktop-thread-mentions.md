# 桌面托管会话的 @ 引用

实现基线：`64ed336`。实现提交以本文件首次提交为准。

## 范围

先支持桌面已经打开并托管的会话。查看会话时选择“通过桌面继续”，通过原生 owner discovery 确认托管状态。输入 `@` 后搜索同一目标机器的会话。保留按 ID 选择的引用，标题相同也能区分。发送通过已有原生 follower start-turn 接口，使用桌面原生引用上下文格式；没有复制历史、增加自建工具执行者或修改原生配置。

能力判断只读桌面自己的 `thread-reference-capability:<id>` 检查点。它来自桌面对 `read_thread` 可用性的判断。缺失或为假时禁止引用发送。该检查点不保证之后每次工具执行都成功，结果仍须核对原始会话。

“交还桌面端”保留会话 ID，但仅释放网页入口。它不会自动打开桌面会话，也不会增加工具。桌面实际打开后可以再次检查托管状态；网页创建的会话若仍没有原生引用能力，会明确提示不可用。普通网页执行通道尚不支持会话引用。

- Node 测试覆盖同目标元数据读取、重复发送去重、交还状态和工具能力分别判断、自身引用及失效引用拒绝、明确失败和结果未知的区别。
- HTTP 测试覆盖 CSRF、Origin 和连接隔离；异步详情测试覆盖切换会话后迟到响应失效。
- Python 测试覆盖只读检查点和原生发送上下文、能力不可用时不派发。
- 备份测试覆盖 RCM 自有的每会话发送回执。不备份原生会话数据。
- ego-browser 在开发预览中使用完全拦截 API 的虚构数据，验证桌面和 390px 布局、16px 输入字体、无横向溢出、键盘选择、焦点保留、发送负载、失败保留草稿和能力缺失提示。
- 中文输入法通过合成 composition/keydown 事件验证确认字不选择或发送。未验证操作系统真实输入法候选窗口。
- 以上属于模拟验证，不代表模型已实际调用 `read_thread`。

## 真实原生验证

功能提交：`2e02eef`。用户在桌面创建专用测试会话并收到 READY 后，通过原生 owner discovery 确认桌面托管、空闲和引用能力。

通过正式网页的原生会话接口另外创建测试源会话，只写入随机验收标记并要求回复 SOURCE_READY。随后通过本次 `NativeAutomations.send` 发送引用到桌面测试会话。发送文本仅包含源会话 ID、标题和读取要求，不包含随机标记或源会话历史。

真实原始事件确认：

- follower start-turn 接收消息并返回轮次 ID。
- 新轮次出现 `mcpToolCall`，`server=codex_app`、`tool=read_thread`、`status=completed`。
- 工具参数的 threadId 与测试源会话一致。
- 最终回复与源会话的随机标记完全一致。
- 没有使用文件读取或终端作为替代工具。

结论：桌面已托管且具备原生读取工具的会话，可通过 RCM 发送原生会话引用。网页创建的会话可作为被引用对象，无需先交还桌面。作为引用发起者时，仍须在桌面打开并确认引用能力；此转换路径和 SSH 目标尚未真实验收。

验证后对测试源会话调用既有交还接口，状态从 waiting 转为 released，确认结束测试使用。测试会话保留，不删除。真实会话标识、随机标记及原始输出保存在仓库外。
