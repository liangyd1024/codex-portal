# 原生定时任务接入调研（2026-10-19）

## 已确定的产品边界

- RCM 与对应目标上的桌面 Codex 共用原生任务，不建设独立调度器、任务副本或双向复制服务。
- 创建、修改和删除通过会话使用原生工具完成；左侧提供“定时任务”浏览入口，展示任务及运行记录，管理操作引导到会话。
- RCM 是展示、同步与操作入口，不修改桌面应用安装内容、引擎实现或原生存储来补齐能力。长期约束见 [AGENTS.md](../AGENTS.md)。

## 本次只读核实

1. 工作区在 master，开始修改前确认无未提交改动并执行 `git pull --ff-only origin master`，结果为已是最新。
2. 从仓库外的连接配置取得本机实际 Codex 二进制路径；其版本为 `codex-cli 0.163.0-alpha.10.2`。
3. 使用该二进制的 `app-server generate-json-schema --experimental --out <独立临时目录>` 导出协议，没有启动、重启或连接任务执行服务。`ClientRequest.json` 包含 172 个请求方法，方法名称中没有 automation、schedule 或 heartbeat，亦未发现相应命名的 schema 文件。这仅证明该版本导出的请求协议没有显式定时任务接口，不证明桌面服务或其他工具完全没有能力。
4. 只读查看已安装桌面应用的 `app.asar`，未解包到安装目录或修改文件。在主进程模块中发现 `automation_update` 原生工具及调度器实现；发现 `automation-runs-updated`、`automation-capability-event` 和 `automation-run-triggered-event` 等通知线索。内部符号和事件不等于对外开放、可稳定调用的接口。
5. 桌面实现同时包含 `automation.toml`、任务及运行记录存储、云端存储迁移、安装身份和账户归属校验。存在“迁移同意后须通过 Automations app 修改”的条件分支。因此不能把旧 TOML 文件视为所有安装状态下唯一且可直接写入的事实来源。
6. 原生工具实现包含 `Automations are only supported for local threads.` 限制分支。不能推定本机桌面可替任意 SSH 目标创建任务；须核实目标主机、原生桌面服务和会话归属的具体支持范围。

本次未读取用户任务正文、未创建或更改任何真实定时任务，未修改 Codex 数据库、配置或安装文件。没有实施 UI 或运行时功能变更。

## 结论与后续验证条件

当前 RCM 使用的 app-server 协议尚未证实可直接管理定时任务。原生桌面应用确有相关能力，但 RCM 如何在保持身份校验和原生执行语义的前提下调用它，仍需验证。当前聊天中可用的桌面工具不代表 RCM 创建的引擎会话自动具备同一工具。

后续应依次核实：

- 是否存在受支持、经身份验证的原生桌面服务或工具接入方式，能够让 RCM 会话调用原生任务工具；不能伪造桌面内部调用身份、注入代码或修改工具配置绕过限制。
- 原生任务列表与运行历史的读取方式、账户及安装归属、迁移状态和更新事件。读取失败或能力缺失应明确展示，不能退回自建任务数据。
- 桌面关闭、目标离线和 SSH 场景下的原生能力边界；不能承诺纯 CLI 目标具备桌面调度能力。
- 在专用测试会话验证会话创建、修改及删除后，桌面和网页读取到相同任务 ID 与状态；确认仅原生调度器执行一次，结果链接到原始会话。

上述调用、双端展示和真实调度均未验证通过。找到内部实现线索不能作为已接通的验收依据。如果没有可用的原生接入方式，应报告阻塞，不以自建调度或直接写原生存储替代。
