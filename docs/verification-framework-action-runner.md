# 操作协调器类型迁移

正式对照保持 `227dbfe`。主控制器中的 action 协调逻辑迁入 `src/web/services/action-runner.ts`，使用严格类型依赖和泛型返回值。保留操作键、busy 集合、重复提交保护、请求卡片恢复、原始错误对象与提示持续时间，以及连接类操作完成后刷新状态的顺序。

迁移前后函数转译后的 token 完全一致，没有调整异常边界或增加调度。协调器只在应用初始化时创建一次，业务命令仍通过原 API 和原生适配执行。

五项新增行为回归覆盖：同键去重与异键并行及返回值；连接、断开、释放三种操作成功或失败后的状态恢复；请求失败时先恢复卡片再报告错误；普通操作失败保留错误原文；错误报告本身失败时仍执行 finally 清理。类型检查、完整 862 项 Node／74 项 Python 测试与构建通过。

桌面 1480×747／DPR 2，以及 iPhone 12 参数的 390×844、844×390、390×480／DPR 3／触控，异步问题共 96 个样本、48 对状态完全一致。覆盖必填、自定义答案、草稿、跳过与恢复、组合输入误发送保护、接口失败、重试等待和完成状态。比较节点文字、属性、计算样式、矩形、焦点、草稿及完整回答请求体。设备参数在导航前后设置，实际参数随样本保存；手机通过触控，组合输入通过事件模拟，不代表实体输入法已验。

维护验收初轮在基准页面出现坐标点击没有发出请求的超时。检查按钮、请求列表与待处理状态后，改用桌面控件选择器点击，正常触发并完成断开。脚本改为桌面可用控件优先使用语义操作，手机仍使用触控；原失败证据保留，没有因该失败修改产品。维护八个流程、四对结果完全一致，覆盖断开／重连的等待、重复点击、完成状态，停止服务确认与取消、拒绝文案、重新加载登录确认与完成。所有草稿与维护请求体保持一致，无页面异常或横向溢出。真实预览结果另行补录。完整迁移、最终全量集成与整体性能门槛仍未完成。

本轮保留已有的同步更新与去重策略，未增加请求、轮询或逐次重建协调器。运行 token 一致仅证明迁移保真，不等于性能测量；[首屏资源差异](verification-framework-startup-resources.md)仍为开放项。
