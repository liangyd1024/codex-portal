# 连接摘要同步提交合并

## 修改边界

在 `renderStatus` 中，将顶部／侧栏连接标识与详情栏连接摘要的两个独立投影合并为一次同步提交。二者之间没有 DOM 读取。各投影仍自行比较字段，只收集实际变化；无变化时不调用 flushSync。收集和执行都在同一同步调用内，不引入微任务、延时、全局待处理队列或另一份连接状态。

其他调用点仍使用各组件原来的同步发布。欢迎按钮的悬停和选区读取、后续控件计算、维护操作、SSE、pageshow、刷新策略、公开接口及 CSS 均保持。本轮不改变上一轮定位出的共同 pageshow 恢复读取。

正式对照为 `227dbfe`。改动前候选为 `8362c3d`，资源 `d688db3042078ae9bade0fad20fe2c2bdbdabe6cff70de12c5ff89020782bada`；改动后隔离构建资源为 `44ed4d81fdeecb3addb105017d0a55c3a3e94e45607ff420a6e8a84f8cde203b`。

## 采样限制

最初沿用旧性能脚本导航首页，没有显式指定会话。两个隔离来源可能恢复不同已保存会话，导致比较范围不同。该轮“减少六次提交”的计数无效，已从结论中排除。修正后的脚本显式指定相同虚构目标和会话，并等待标题与正文就绪后开始；保留正常 React 调试扩展，计数包装向原 hook 传递原 this 和全部参数，结束后在 finally 恢复。

本项不会单独证明整体性能门槛通过。首屏资源、同步及端到端响应需要分开记录，不用较少 React 提交次数替代整体耗时证据。

## 校准后的提交计数

同一虚构会话上，桌面和 iPhone 12 竖屏分别按旧／新／新／旧执行。每组 45 次连接状态切换，排除前五次，共 320 个有效样本。当前状态事件均由夹具提供，没有真实维护写入。

旧候选通常为每次 15／12 次提交，新候选为 14／11 次，随连接方向交替。旧候选首组另有两次 14 次提交，保留这些异常样本，不将全体样本描述成严格减少一次。其余七组方向对应计数稳定，支持合并两次状态投影减少一次重复提交的限定结论。

| 设备 | 旧候选同步／两帧后中位数（两组，ms） | 新候选同步／两帧后中位数（两组，ms） |
| --- | --- | --- |
| 桌面 | 4.70／16.60、5.50／16.60 | 5.60／16.70、5.25／16.70 |
| iPhone 12 模式 | 6.00／16.70、6.20／16.55 | 6.05／16.70、6.00／16.70 |

同步耗时未显示稳定改善，两帧后耗时基本一致；不能据较少提交次数宣称页面整体提速。初始未指定会话的无效轮次未用于此表。所有校准样本标题匹配同一会话，无页面错误或横向溢出。
