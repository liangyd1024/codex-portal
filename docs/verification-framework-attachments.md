# 附件迁移与鼠标事件补验

## 版本与范围

以下鼠标诊断轮次的产品为 `da9cb89`，构建资源 `e8900839`，正式基准为 `227dbfe`。本轮只补验和更新记录，没有修改产品代码、重启正式服务或操作真实会话。前轮添加图片按钮迁移、文件选择入口、键盘与触控、性能及完整测试见[持续报告](verification-framework-parity.md#添加图片按钮-react-所有权与复验)。

## 高级鼠标操作失败的定位

前轮附件预览／移除的高级鼠标操作没有完成，键盘操作可完成。本轮在两个隔离版本记录捕获阶段的 pointerdown、mousedown、mouseup、click、焦点、页面可见性和附件节点替换。所有测试使用虚构会话与图片。

1. 先用选择器 click 检查两版，从输入框或搜索框起始焦点分别点击预览和移除，共八个样本。全部在工具重试中超时；页面没有收到 pointerdown、mousedown 或 click，但附件卡片已多次重建。因此该结果不能直接证明产品按钮 click 处理器失败。
2. 在 master 隔离页给附件列表的 replaceChildren 增加只记录调用栈的包装。调用链来自前台恢复后的 loadStatus／refreshSelected，经 renderControls 重建卡片；没有改变返回值或阻止原方法。下一次导航后该临时包装失效。
3. 再比较坐标鼠标工具和 CDP 鼠标事件，共八个样本。坐标工具的四个样本均观察到 visibilitychange 隐藏／恢复；刷新将按下时的节点替换，松开落在另一个节点上，没有 click。CDP 的四个样本没有这次可见性切换，均产生 click，预览打开或卡片移除。两版结果一致。

这些证据将问题定位为高级工具操作期间的页面恢复与原有重建行为相互影响，不是已证实的框架迁移缺陷。没有通过关闭刷新、移除可见性监听、禁用 React 调试回调或修改按钮业务逻辑来取得通过结果。

## 补验方式

保留同一 ego-lite 空间和页面。桌面附件卡片先检查稳定几何位置与命中目标，再使用 CDP 的 mouseMoved、mousePressed、mouseReleased。手机仍使用触控事件。该方式派发浏览器鼠标事件，不能写成物理鼠标或实体 iPhone 实测。高级工具失败的样本继续保留，不重新归类为通过。

覆盖桌面 1480×747／DPR 2，以及 iPhone 模式 390×844、844×390、390×480／DPR 3／触控 1。最终对照包括处理中的会话切换、迟到图片完成、返回原会话、预览、关闭、移除就绪图片、处理中移除后不复活，以及主聊天和侧聊图片隔离。

最终主聊天 64 样本／32 对、侧聊 48 样本／24 对全部一致，无页面异常或横向溢出。对照节点结构、文案、矩形、样式、图片草稿、预览状态与模拟请求；侧聊仅排除随机创建请求 ID，没有归一化节点、样式或行为差异。此前高级鼠标操作失败不再单独作为迁移差异；其工具限制仍明确保留。

本轮为浏览器诊断及复验，没有源码变更，因此没有重复运行应用测试或更新服务。运行版本仍为 `da9cb89`。附件外壳、隐藏文件输入、dialog 容器、其他界面迁移、整体性能与真实 SSH 等缺口继续保留，本项通过不代表整体验收完成。

## 附件容器与文件输入迁移

产品 `c4d0b0f`，干净资源 `86dea361`，正式对照仍为 `227dbfe`。远端 master `0a3ee2a` 只增加文档。本轮将附件列表外壳、隐藏 file 输入、预览 dialog 容器及其 change／遮罩点击事件迁入 React。安装时保留列表在表单中的原始顺序；剪贴板适配仍只切换选区标记类，组件不覆盖该标记。原生 showModal／close 和会话切换关闭保持原语义。图片压缩、数量限制、草稿存储、请求与发送逻辑未改变。

使用正常 ego-lite 环境，保留调试回调；桌面附件卡片使用已核实的 CDP 鼠标事件，手机使用触控。视口与前述四视口相同。

| 流程 | 样本／对数 | 结果 |
| --- | --- | --- |
| 主聊天异步图片、会话切换、迟到完成和移除 | 64／32 | 一致 |
| 主聊天／侧聊隔离、预览和关闭 | 48／24 | 一致 |
| 实际浏览器文件入口、选入图片和全选删除 | 16／8 | 一致 |

对照另增加表单直接子节点顺序。节点、文案、样式、矩形、草稿和请求一致；仅侧聊排除随机创建请求 ID。全部样本无页面异常或横向溢出。

剪贴板专项覆盖：全选图文、状态刷新后保持标记、copy 提取完整文本与图片、cut 清空、工具 keyboard.paste 经浏览器粘贴恢复图文、ArrowRight 清除全选标记、Escape 关闭预览、点击 dialog 遮罩关闭以及全选删除。copy／cut 使用 ClipboardEvent 和 DataTransfer 模拟，不写入用户系统剪贴板；paste 使用工具的剪贴板保存／恢复能力。这是桌面 Chromium 及设备模式验证，不等于 iOS 系统选区、剪贴板菜单或软键盘实测。

与前版资源 `e8900839` 比较四张就绪图片的输入事件到强制布局耗时。桌面与手机按 ABBA 顺序各四组，每组 60 次去掉前十次，共 400 个有效样本；构建和完整测试已在采样前完成。

| 场景 | 前版组中位数 | 本轮组中位数 |
| --- | --- | --- |
| 桌面 | 2.70–2.80 ms | 2.80–2.90 ms |
| iPhone 竖屏 | 2.90–3.10 ms | 2.90–3.00 ms |

首轮差值较小，不能据此确认无退化。随后扩大到 2,000 个有效样本：桌面前版组中位数 2.90–3.00 ms，候选 3.05–3.20 ms；手机前版 3.00 ms，候选 3.10–3.15 ms。因此该候选性能未通过。类型检查、820 Node／74 Python 完整回归和构建通过，提交后干净产物摘要与隔离候选一致。

只读检查浏览器监听器发现：新附件 portal 使主表单增加 React 的 input 捕获／冒泡监听，而前版主表单没有这组监听；主输入事件因此经过额外的事件分发范围。后续候选将主聊天附件直接置于现有 React 表单树，保留节点顺序，不增加 DOM 包装。该修复仍需独立功能与性能复验；不能只凭监听器减少宣布性能通过。

## 主表单事件分发修复与复验

产品修复 `1fb2c05`，资源 `7c82b343`。主聊天附件直接渲染在原 React 表单树内；侧聊保留独立入口。列表和隐藏文件输入保持原始顺序，不增加包装节点。只读检查确认主表单监听器与前版相同，均为一个监听器且没有额外 input 监听。

修复后重新执行上述四类流程，共 208 样本／104 对。节点顺序、文案、样式、矩形、草稿、请求和弹窗状态全部一致，页面异常与横向溢出均为零。保留正常调试回调，未禁用刷新。类型检查、820 Node／74 Python 和构建通过；提交后构建资源与受测候选一致。

性能独立比较前版资源 `e8900839` 和修复资源 `7c82b343`，每项按桌面与手机 ABBA 顺序采样，共各 2,000 个有效样本。每组 260 次，去除前十次；指标为输入事件至强制布局。

| 场景 | 前版组中位数 | 修复组中位数 |
| --- | --- | --- |
| 主聊天桌面 | 2.80–3.10 ms | 3.10 ms |
| 主聊天 iPhone 竖屏 | 3.10–3.20 ms | 3.00–3.20 ms |
| 侧聊桌面 | 2.30–2.35 ms | 2.30–2.35 ms |
| 侧聊 iPhone 竖屏 | 2.20–2.30 ms | 2.25–2.30 ms |

此前两种视口共同出现的稳定增量没有重复出现。主聊天桌面仍存在顺序／时间波动，不能据此声明整体性能通过或框架提速。侧聊单独测量，不能以主聊天结果代替。所有样本均为隔离虚构数据；真实 SSH、其他性能门槛及剩余迁移继续保留。
