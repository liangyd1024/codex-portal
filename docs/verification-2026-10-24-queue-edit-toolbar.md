# 排队消息编辑与目标栏对齐

## 修改与依据

按用户提供的排队消息及目标栏截图，沿用目标栏的紧凑布局和编辑方式。顺序为运行提示、目标栏、排队消息、输入框。每条消息单行省略展示；点击内容打开编辑框，右侧依次为删除、引导（空闲时为发送）。长正文在编辑框完整显示。队列消息先后仍使用原生返回顺序。

复用目标栏样式与编辑弹窗样式。原生依据补充当前配置指定二进制的 `app-server generate-json-schema --experimental`：`thread/queue/update` 接受 threadId、queuedSubmissionId、input。新增独立 queueEdit 能力检查并升级协议缓存策略；不支持时禁用编辑。

服务端先读取原生队列，核对旧文字，再原地更新。保留非文字输入、消息 ID 和排队位置，不删除重建、不启动轮次、不建立本地队列。原生接口没有条件更新字段；读取与写入之间仍存在跨入口修改窗口，继续遵守同一会话只从一个入口操作的约定。

编辑支持保存、取消、重新读取。失败保留当前页面的编辑草稿；切换连接或会话关闭编辑框，迟到响应不操作另一会话的弹窗。编辑草稿暂存在当前页面内存，页面重新加载后不保留。主输入框草稿不受编辑影响。

## 验证

- 原生服务：使用独立 app-server 和专用测试会话，在运行轮次内 queue/add → queue/update → queue/list，修改后的文字正确，队列 ID 与 clientUserMessageId 不变。删除测试队列项并归档测试会话。未操作业务会话。
- 初次空闲会话探测：原生自动消费队列，更新返回 queued submission not found。未把该探测记为通过；后续使用运行中专用测试会话完成验证。
- 单元与 HTTP：覆盖更新路由、原生身份与附件保留、内容冲突、消息被消费、无变化跳过写入、协议缺少更新能力。完整 `npm test`：696 项 Node、74 项 Python 通过。
- ego-browser 隔离组件：直接加载本次真实组件和 index.html 顺序的全部样式，API 使用模拟数据。桌面 1280×900，目标栏与两条队列均宽 880px、高 46px、1px 黑边。已检查桌面与手机截图。
- 桌面交互：编辑保存、取消后草稿保留、失败反馈、保存中禁用、重新读取、切换会话关闭、断线禁用、键盘进入和 Tab 焦点、悬停反馈通过。中文组合事件期间触发提交没有请求。全选、剪切、粘贴及多行中文通过浏览器模拟验证。
- 移动设备模式：iPhone 12/14 共用 390×844，iPhone 17 为 402×874，横屏 844×390，缩短可视高度 390×500；均 mobile=true、DPR 3、5 点触控。通过触控事件打开编辑和保存；各场景条目高 46px，无页面横向溢出。
- 性能抽样：两条队列数据不变时连续 render 1000 次，约 0.4ms，原节点保持不变，无新增请求。沿用版本签名去重，不新增轮询。此抽样不代表整体性能最优。

## 限制与部署

开发预览端口由另一项目使用，未停止或更换该服务。本次 UI 验证是隔离组件模拟，不是完整预览应用验收。正式安装另按标准流程检查版本接口及真实工作台加载。

实体 iPhone、真实软键盘、中文候选窗和系统选区手柄未测试。SSH 目标和真实图片编辑未实测；非文字输入保留通过服务端回归测试验证。原生队列仍可能在编辑时被消费，此时保存失败并保留草稿，不重新排队或自动发送。
