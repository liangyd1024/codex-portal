# 单会话交还验证（2026-10-18）

## 范围与结论

本次实现“先完善交还流程，可以接受释放时等待”：在会话操作菜单中选择“交还桌面端”，只退订当前会话，保留草稿，并持久记录不再自动接管的意图。没有引入每会话独立引擎，也没有部署到正式服务。

当前本机引擎 `0.163.0-alpha.10.2` 的 `thread/unsubscribe` 不能立即释放会话写入占用。退订返回成功后，第二个引擎仍然收到 `already has an active writer`。界面因此区分“等待释放”“结果待确认”“已确认释放”，不会把退订成功当作桌面已经可以继续。

[官方 App Server 说明](https://learn.chatgpt.com/docs/app-server#unsubscribe-from-a-loaded-thread)描述：最后一个订阅退出后，需要没有订阅和会话活动约 30 分钟才卸载。此时间是文档所述条件，不是本次测得的固定倒计时；其他入口仍订阅时可能继续等待。

## 实现边界

- 交还前检查当前会话的轮次、目标、后台命令、排队输入、待处理请求和尚未完成的操作；运行中或无法确认时拒绝交还。不会中断任务、终止命令或停止目标服务。
- 在发送退订之前保存交还意图。超时或断线后仍禁止自动接管；只有明确点击“在网页继续”才重新订阅。
- 通过 `thread/closed` 或完整分页的 `thread/loaded/list` 确认卸载。交还后的历史读取走只读快照，不持续读取引擎中的该会话。
- 重连保留其他会话原有恢复方式。交还状态单独保存在管理器数据目录的 `.handoffs.json` 中，原订阅文件排除已交还会话；该状态纳入现有管理器备份与恢复白名单。
- 本功能没有新增跨入口锁。其他入口的同会话订阅不会被强制断开，也不以停止共享服务缩短等待。

## 真实引擎验证

启动两个独立的临时引擎进程，只创建专用测试会话；未接管现有工作会话，没有调用停止共享服务接口。

1. 初始探测：对空闲会话退订后，在约 0.012、0.241、1.253、4.268 秒尝试从另一个引擎恢复，均仍被写入占用拒绝。另一测试会话的命令正常完成。
2. 使用实际 `Manager.handoff` 集成验证：会话 B 执行有界的 `sleep 12` 命令时，交还 B 被拒绝；交还空闲 A 返回 `waiting`，第二引擎恢复 A 仍被占用拒绝；B 继续运行并正常完成。
3. 测试结束只关闭本次创建的临时引擎进程。
