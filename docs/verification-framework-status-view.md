## 实现与行为回归

主控制器的连接状态应用和页面会话登记分别迁入严格 TypeScript 服务。连接状态继续复用原生版本选择算法，保留未知字段和原始对象引用；连接变化继续使旧详情、控制权限和侧栏活动失效。页面登记保留页面 ID、递增版本、请求合并、当前响应判断和失败重试；SSE 恢复仍先清除登记缓存，再登记当前会话。没有改变 HTTP 字段、路径、原生数据或存储格式。

31 项相关测试通过，覆盖迟到详情、切换与切回、交还、桌面回执、恢复缓存、连接实例变化、登记去重、错误重试和未知字段保留。首次接线时，一项测试仍通过改写固定主机变量制造新登记，与生产中固定主机、切换后页面导航的流程不同；改为改变连接时间，保留“旧失败不能清除新请求，当前失败可重试”的原断言。类型检查、构建和完整 835 Node／74 Python 通过。

## 浏览器对照

使用 ego-lite，同一页面、正常 React 调试／扩展环境。正式固定源码与候选均在无原生 Manager 的隔离服务上运行，未拦截 API 返回 503。真实写请求未进入任何目标。

设备参数：桌面 1480×747／DPR 2／无触控；iPhone 12 390×844、844×390、390×480／DPR 3／触控 1。导航后再次核对参数，手机按钮使用触控。

- 连接维护四视口新旧流程一致：断开与连接的等待及重复点击、恢复、维护确认取消、拒绝反馈、账号恢复反馈、最终草稿与完整请求序列。所有写操作均为模拟，不代表真实停止服务或账号管理验收。
- 浏览器原生 EventSource 对隔离 HTTP 服务执行三轮断开和恢复，四视口共 24 样本／12 对一致。每次恢复只增加一次会话登记，版本依次为 1、2、3、4；每阶段仅一个有效流，草稿保留、正文节点稳定、无页面异常或横向溢出。对比请求时仅规范化随机页面 ID，其他字段原样比较。
