# 当前候选跨目标草稿与历史导航验证

## 版本与范围

基准为正式 4317 的 `227dbfe93ee88718c2437f7b7c7b119570a720a6`。候选为 `e1a5f0c90e8937cc5bce1ed7bc5d6b1a6083296c`，干净构建资源摘要为 `b172b6030f2253b03ecf5bf30b347d7d9fb6f38122d9ee1e71168f80f2b6feaa`。结果整理时重新读取 4317 与 4327 版本接口，均为上述版本且返回 200。

本轮仅新增隔离浏览器夹具与报告，没有修改应用代码、重启服务或部署正式环境。夹具 `test/fixtures/connection-scope-browser.js` 为两个虚构目标提供不同身份、路径、正文与模型名称，故意复用会话 ID，检查浏览器存储是否按目标隔离。关键接口收到非当前目标参数时返回失败并登记违规。模拟 SSH 目标不连接真实机器。

使用 Ego Lite 的 Chrome 页面，保留正常调试扩展。桌面为 1480×747、DPR 2、无触控；iPhone 12 兼容参数为 390×844、DPR 3、触控启用，补充 844×390 横屏及 390×480 可视高度缩小场景。每个样本均核对实际视口、DPR 和触控参数。短高度不代表真实软键盘验证。

## 行为结果

| 流程 | 样本／对照组 | 结果 |
| --- | --- | --- |
| 本机同 ID 会话输入草稿并添加图片，切换远程空草稿，输入远程草稿，再分别返回并清理 | 48／24 | 界面与存储对照一致；正文、模型、选中目标、草稿和图片没有串目标 |

合计 88 个样本、44 组对照。比较包含正文、输入值、高亮层、图片数量、模型选项、两个目标的草稿存储、节点几何与样式及禁用状态。仅端口和单独审计的请求序列不纳入界面相等判断。样本没有页面错误、横向溢出、目标范围违规或业务写请求。所有记录的关键读取都带当前目标参数；选中目标、页面目标和保存的目标一致。各流程结束后清空测试草稿与图片。

历史导航使用浏览器历史条目 ID，不以重新输入 URL 代替。记录到的 pageshow.persisted 全部为 false，所以只证明普通历史导航恢复，不证明 BFCache 恢复。这里只验证目标切换后的状态隔离，不据此宣称覆盖所有跨目标迟到响应。

## 请求差异与限制

目标选择流程有 11／24 组关键读取序列不同，历史导航有 4／20 组不同。保留了原始请求顺序与次数，没有为了得到一致结果而归一化。目标选择流程的次数差异两个方向都有；本轮没有足够调用追踪确定原因。界面和存储对照通过不能替代请求一致性或性能门槛通过。后续须定位重复读取及触发时序，并继续验证最终候选。

完整回归为 884 项 Node 测试、74 项 Python 测试通过。夹具语法检查通过。没有应用代码变化，因此未重复构建或重启预览；沿用上面列明的干净应用构建。

真实 SSH 只读身份重试仍在约 15 秒后连接超时，未进入身份验证。未操作原生会话或任务。模拟远程目标结果不能替代真实 SSH 验收。实体手机输入法、系统选区及剪贴板不在本轮设备模拟结论内。

原始样本、截图及命令日志保存在仓库外。本报告是限定范围证据，整个框架迁移与最终全量验收仍未完成。

桌面与 iPhone 12 竖屏各按基准、候选、候选、基准顺序导航，共八个样本。记录至请求流安静一秒，尚未到五秒定时同步窗口；各样本实际设备参数正确，没有页面错误或目标范围违规。

## 追加：详情延迟刷新与选择读取的时序差分

针对上述详情读取次数差异，新增 `test/detail-refresh-timing.test.mjs`。测试组合当前实际 detail-reader、selected-refresh 和 update-scheduler 模块，使用可控时钟及延迟完成的模拟 HTTP 响应。没有访问真实目标或改变产品计时参数。

另从正式基准 `227dbfe` 的 public/app.js 提取实际 readSelectedDetail、refreshSelected 和 scheduleDetailRefresh，在仓库外的隔离 VM 中执行完全相同的三组时间线。基准与当前实现均通过以下行为断言：

| 时序 | 两版共同结果 |
| --- | --- |
| 初次冷读取已安排延迟刷新；1600 毫秒开始重新选择，完整读取在 1650 毫秒时仍未完成 | 650 毫秒调度到期时复用进行中读取，共四次详情请求，无额外请求 |
| 同样重新选择，但完整读取在 1620 毫秒完成 | 1650 毫秒执行一次额外温读取，共五次详情请求；不携带 preview／fast 冷读取参数 |
| 1600 毫秒重选旧会话，1620 毫秒改选新会话，两个读取交错完成 | 调度使用当前选择并与其进行中读取合并；旧响应不能覆盖新会话 |

这些结果证明：在已测的相同输入与响应时序下，两版冷读取、延迟调度和合并逻辑一致；已有浏览器次数差异存在可复现的共有时序解释。因此本轮不改变应用调度行为。它不证明此前四个浏览器样本必然由同一计时路径触发；原始样本的调度来源仍未直接记录，继续保留该限制，也不作整体性能通过的结论。
