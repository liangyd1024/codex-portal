# iPhone 12 连接提示框边界修复

日期：2026-10-22。

## 问题与修改

用户反馈连接加载期间的黑色 Tips 超出屏幕，并提供手机截图。使用现有提示组件复现：390px 宽视口中，提示框横向边界为 203…569px，关闭按钮不可见。原因是 composer.css 旧手机规则取消 transform 并增加左右 margin，而后加载的 mobile-ui.css 仍使用 left:50%。

删除输入组件中旧的提示区域布局规则，手机提示定位统一由 mobile-ui.css 管理。两侧至少保留 12px，并兼顾安全区；使用左右边界和自动 margin 居中。高度按现有 visualViewport 变量约束。超长信息在正文区域内换行、滚动，关闭按钮不随长文本滚出视口。桌面定位及原有自动消失时长不变。

## 验证方法

使用 ego-browser 和开发预览，独立临时状态目录。模拟 API/SSE，没有向真实引擎发起业务变更或主动断开真实连接。复现和边界测试调用实际 createToasts 组件，注入虚构连接错误及长 URL。另观察到模拟连接失败和恢复请求及恢复提示；不将此视为真实网络断线认证。

设备模拟使用 iPhone 12 参数：390×844、DPR 3、mobile、5 点触控、coarse pointer。启用后核对参数；关闭按钮及文本滚动使用触控事件。增加 390×664、390×500 可用高度，以及 844×390 横屏。可用高度缩小不能替代真实 Safari 工具栏和软键盘。

| 场景 | 提示边界（CSS px） | 结果 |
| --- | --- | --- |
| 390×844 普通连接错误 | x=12…378，y=64…126 | 关闭可点，无横溢出 |
| 390×664 超长错误 | x=12…378，y=64…648 | 文本内部滚动，关闭可点 |
| 390×500 超长错误 | x=12…378，y=64…484 | 触控滚动成功，关闭可点 |
| 844×390 横屏长错误 | x=202…642，y=64…374 | 居中，无横溢出，关闭可点 |
| 390×844 侧栏打开时 | x=12…378，y=774…836 | 底部提示保持屏幕内 |
| 1440×900 桌面短提示 | x=516.5…815.5，y=800…870 | 原有桌面定位正常 |

短提示、超长提示截图已查看。触控关闭和原有 3 秒自动消失通过，未记录 JavaScript 错误。完整 `npm test`：419 项 Node.js、69 项 Python 测试通过。`git diff --check` 通过。未实测实体 Safari、真实安全区和系统软键盘；用户提供的截图仅作为修复前证据，不作为修复后通过证明。

验收中一次初始触控配置在导航后未保留，重新启用并核对后执行；刷新错误不一定产生 Toast，故改用实际提示组件检查边界；多个提示中仅最新提示可见，最终测量和触控均针对最新提示。未将这些验收脚本问题误记为产品通过项。
